# 리벤 OCR·오버레이 및 두캇 표기

## 구현

- 앱과 성유물 오버레이의 사용자 표시 문자열을 `듀캇`에서 `두캇`으로 통일했다. 데이터/API의 `Ducats` 식별자는 유지한다.
- 리벤 상단에 `화면 인식 · 오버레이`를 추가했다. 근접·소총·산탄총·권총을 지원하며 종류와 랭크 설정은 재실행 후에도 유지한다.
- `Ctrl + Shift + V`는 전경의 워프레임 화면만 캡처한다. 게임 활성화, 입력 전송, 자동 옵션 채택은 하지 않는다. 게임 실시간 캡처는 기존과 같이 FHD 이상이다.
- 한국어 리벤의 좌우 카드를 분리한다. 반전·임계값 전처리 결과와 기존 리벤 범위를 대조하고, 수치·부호·단위·옵션 구성에 문제가 있으면 확인 필요로 표시한다. 이름·수치·부호를 임의로 보완하지 않는다.
- 수율은 최소~최대 범위 안의 위치이며 획득 확률 또는 빌드 점수가 아니다. 음옵은 절대 크기를 비교한다. 종류·랭크는 OCR로 추측하지 않고 설정값으로 표시한다.
- 기존 `RivenValues`, `RivenEngine`, `RangedRivens`, 각 Workshop의 범위·접합 계승식·옵션 풀을 재사용한다. 접합 가능한 조합 수와 조합마다 무작위로 들어올 수 있는 대체 옵션 종류 수를 구분한다. 기존 접합 옵션이 있는 카드의 재접합 예측은 제공하지 않는다.
- 앱에서 스크린샷 불러오기, 클립보드 이미지 인식, 원문 교정, 인식 취소, 기존 리벤 작업실로 가져오기가 가능하다. 가져오기는 분석 입력만 변경하며 게임에 입력하지 않는다. 코스트·극성은 추측해서 채우지 않는다.
- 오버레이는 클릭 통과·비활성 네이티브 창이다. 전경 게임이 바뀌면 닫히고, 30초 후에도 닫힌다. 단축키로 다시 읽을 수 있다.
- 자동 감지는 로컬 `EE.log`에서 관찰한 `RivenEvolution.lua` 로그가 새로 기록될 때 동작한다. 과거 로그를 재생하지 않으며 전체 화면 OCR을 상시 폴링하지 않는다. 신호가 없는 화면은 단축키로 읽는다. 설정 변경·종료 시 오래된 요청을 취소하고 결과를 적용하지 않는다.

## 검수

- Release 빌드·Windows x64 self-contained publish 성공.
- 전체 Core 회귀: 1,571개 통과, 0개 실패. 이후 입력 누락 검사를 보강한 최종 코드에서 리벤 집중 검사 41개 재통과.
- 리벤 화면 인식/UI 검사: 최종 배포 파일 기준 26개 통과.
  - 한국어 시험 카드 2장, 총 6옵션의 이름·수치·부호 일치 및 전처리 교차 확인.
  - 1920×1080: 1.216초, 2880×1620: 1.152초. 합성 시험 화면의 해당 실행 측정값이며 실제 게임의 지연 보장이 아니다.
  - 빈 화면에서 리벤 결과를 생성하지 않음.
  - 실제 WPF Automation 버튼 호출로 창 열기, 잘못된 수치 교정, 접합 예측 차단·복구, 랭크 변경, 네 종류의 작업실 가져오기 확인.
  - 작은 창·150% 배율 및 1200/960 너비 오버레이 렌더링 검토.
  - NOACTIVATE/TRANSPARENT/TOOLWINDOW 스타일 확인.
  - 과거 로그 무시·새 로그 감지 확인.
- 기존 WPF `--smoke` 성공. 성유물 자동 감지 검사 15개 성공.
- UI 검사는 별도 Windows 데스크톱에서 수행했고 입력 데스크톱으로 전환하지 않았다. 사용 중인 게임과 기존 WF Labs 프로세스는 중지·재시작하지 않았다.

## 실전 확인이 남은 범위

- 이번 사용자 첨부는 성유물 보상 화면이다. 실제 한국어 리벤 카드·순환 화면의 OCR 정확도, 새 로그와 실제 옵션 변경의 대응, 게임 위 오버레이 배치는 아직 실전 검증하지 않았다.
- 종류와 랭크 자동 판별은 구현하지 않았다. UI와 오버레이 모두 설정 기준임을 표시한다.
- 순환 화면의 왼쪽/오른쪽을 현재/새 옵션으로 단정하지 않는다. 카드 위치만 표시하며 어떤 옵션을 채택할지는 사용자가 게임에서 선택한다.
