# WF Labs v0.5.1 모딩 작업 공간 수정 — 2026-10-11

사용자가 지적한 보관함 부족과 과도한 입력창 높이를 수정했다. v0.5의 기능 검사와 비표시 렌더링 검사는 실제 보관함의 가시 영역을 충분히 검증하지 못했다. 특히 이전 검사는 화면 밖 자식의 높이가 180 이상이고 왼쪽 전체가 스크롤된다는 사실을 성공으로 판단했다. 이번에는 실제로 화면 안에 온전히 보이는 카드 수와 위치를 검사한다.

## UX 제1원칙

상세한 정보를 제공하되 사용법 설명 없이 쉽게 사용하게 한다. 익숙한 선택창·검색·드래그·정렬·상태 표시를 사용하고, 상세 설정은 펼치기/팝업/툴팁으로 제공한다. 오류·용량 초과·계산 미지원은 숨기지 않는다. 이 원칙을 AGENTS.md, 개발명세, UX_PRINCIPLES.md에 기록했다.

## 수정

- 무기군과 무기 이름을 맨 위 한 줄로 정리했다. 스탠스·동작 선택은 포르마 설정·8칸 비우기 옆에 배치했다.
- 장비 제목과 반복된 수직 여백을 제거해 상단 설정을 116 DIP로 줄였다. 사용/최대 수용량·초과 표시는 유지하고 상세 설정은 팝업으로 옮겼다.
- 장착 카드 높이는 104 DIP, 보관함 카드는 68 DIP다. 이름은 최대 두 줄, 상세 정보는 기존 호버/키보드 포커스 설명에 남긴다.
- 왼쪽 영역의 940 DIP 고정 높이와 전체 스크롤을 제거했다. 설정·장착 슬롯은 고정하고 남은 영역을 보관함에 배정한다. 검색/정렬/필터와 모드 목록을 한 화면에서 조작한다.
- 계산 방식 선택창은 높이 32 DIP로 고정하고 수직 가운데 정렬했다. 옆의 제목과 설명 높이에 맞춰 늘어나지 않는다.
- 많은 모드 때문에 스크롤 손잡이가 짧게 잘리는 문제도 수정했다. 최소 트랙 손잡이는 28 DIP다. WPF Track의 최소 길이 계산을 확인하고 스크롤바 범위의 리소스로 지정했다. 근거: https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Controls/Primitives/Track.cs

## 실제 가시 영역 검사

| 창 크기 / 조건 | 온전한 카드 | 온전한 줄 | 손잡이 높이 |
|---|---:|---:|---:|
| 1520×1000 | 15 | 5 | 58 DIP |
| 1240×730 · 최소 창 | 6 | 2 | 28 DIP |
| 1240×730 · 보관함 끝 스크롤 | 5 | 2 | 28 DIP |
| 1366×768 | 6 | 2 | 28 DIP |
| 1536×816 · 125% 이미지 | 9 | 3 | 28 DIP |
| 1280×760 · 150% 이미지 | 6 | 2 | 28 DIP |
| 1920×1080 | 24 | 6 | 109 DIP |

마지막 행에 모드가 2개만 있는 목록 끝은 3+2개가 두 줄로 보이는 정상 상태다. 창 크기는 외부 프레임을 포함한 논리 크기이며 모니터 픽셀 해상도와 구분한다. 125%/150%는 이미지 렌더링 배율 검사다. 실제 다중 모니터 이동을 검증했다는 뜻이 아니다.

모든 경우에서 무기군·무기의 줄 정렬, 스탠스와 편집 도구 배치, 설정·슬롯·보관함의 화면 이탈, 카드 두 줄 가시성, 스크롤 손잡이 잘림을 검사했다. 최소 창에서 보관함을 끝까지 스크롤해도 장착 슬롯 좌표가 바뀌지 않는지 확인했다. 생성한 최소·기본·배율 이미지를 눈으로 확인했다.

배포 EXE의 UI smoke 종료 코드 0. 실제 화면 밖 HWND에서도 모딩 작업 영역 검사 통과, PerMonitorV2=true, 96 DPI, Wanted Sans 확인. 기존 계산·저장 검사 141개 통과, 실패 0개. 현재 시험은 컨트롤 상태·레이아웃·일부 네이티브 창 동작 검사이며 OS 마우스 드래그 전체 경로의 자동화는 아니다.
