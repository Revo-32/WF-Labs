# WF Labs v0.5.4 — 작은 그래프 글자 보완

2026-10-11

사용자가 보낸 도넛의 ‘비치명 합계’는 Charts.cs에서 11 DIP로 지정되어 있었다. v0.5.3에서 렌더링을 바꾸었지만 이 작은 글자 크기를 놓쳤다. 이번에는 폰트 이름만 바꾸기 전에 실제 WPF의 동일 조건 비교를 수행했다.

## 비교와 판단

Wanted Sans와 설치된 Malgun Gothic(맑은 고딕)을 같은 문구·배경·색·렌더링으로 11/12/13/14/16 DIP에서 비교했다. 100/125/150%에서 시각 트리와 비트맵 DPI를 함께 적용했다. PNG를 확대해 배율 검사를 대체하지 않았다.

이 환경의 비교 이미지에서는 폰트 교체보다 크기를 14 DIP로 키우는 쪽의 개선이 뚜렷했다. 이는 정량적 사용자 연구 결과나 모든 모니터에 대한 보장은 아니다. Wanted Sans를 유지하며, 맑은 고딕 파일을 배포하거나 새 폰트 의존성을 추가하지 않았다.

## 적용

- 도넛 가운데 한글: 11→14 DIP. 합계 숫자: 17→20 DIP.
- 도넛 범례: 12→14 DIP. 눈금·현재 위치 등 그래프의 나머지 글자는 최소 13 DIP, 축 제목은 13~14 DIP.
- 실제 FormattedText 너비로 가운데를 정렬한다. 글자 수에 고정 폭을 곱하던 추정을 제거했다.
- 커진 글자가 원과 겹치지 않도록 도넛 반지름을 조정하고, 눈금의 왼쪽 공간을 늘렸다.
- Wanted Sans와 기존 DPI별 배치·Grayscale 설정은 유지한다. 계산 데이터와 저장 형식은 변경하지 않았다.

## 검증

- Release 빌드: 경고 0, 오류 0. 배포 EXE의 --smoke 종료 코드 0.
- 계산 검증 141개 통과, 실패 0.
- 기존 정렬·카드 마감·툴팁 상호작용, 네이티브 창 검사 통과.
- 7개 창 크기/배율 레이아웃 검사 통과. 최소 1240×730에서 보관함 온전한 2줄 유지.
- 실제 렌더링 이미지에서 기본 창, 최소 창, 150%의 도넛 가운데·범례·그래프 눈금이 서로 겹치거나 잘리지 않는지 육안 확인.
- 100/125/150% 폰트 비교 PNG 생성. 실제 모니터 간 이동이나 사용자 디스플레이의 육안 검증을 대신하지 않는다.

## 참고

Microsoft Windows 타이포그래피 가이드는 본문 14 epx, 작은 캡션 12 epx를 예시로 든다. 한국어를 담는 이 앱의 도넛 라벨은 비교 결과에 따라 14 DIP로 결정했다.

- [Typography in Windows](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)
- [Malgun Gothic](https://learn.microsoft.com/en-us/typography/font-list/malgun-gothic)

비교 화면은 Grayscale을 쓰는 현재 앱 조건이다. ClearType 환경을 포함한 모든 조건에서 특정 폰트가 우월하다고 결론 내리지 않는다.
