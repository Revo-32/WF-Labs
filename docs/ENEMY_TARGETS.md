# WF Labs 0.6.3 · 적 선택과 상황 설정

2026-10-11. 새 대상 선택 기능은 팩션 → 적 → 화면에 표시되는 레벨 → 일반 / 강철의 길 / 빙주령 순서다. 자동 계산된 체력·실드·방어력을 바로 보여 주고, 결과 영역에도 적 이름·레벨·난이도를 표시한다. 직접 입력은 적 목록의 `직접 입력`을 선택했을 때만 나타난다. 이전 저장 파일의 수동 체력·방어력·실드·오버가드는 그대로 복원한다.

## 자료와 지원 범위

`data/enemy-catalog.json`에 일반 적 31종, 11개 팩션/하위 팩션을 연결했다. 그리니어·쿠바 그리니어, 코퍼스·코퍼스 아말감, 인페스티드·데이모스 인페스티드, 오로킨, 속삭임, 스칼드라, 테크병, 아나키스트다. 선택 ID는 Wiki 모듈의 게임 내부 경로다. 한국어 이름은 앱 표시명이며 영문 위키 이름을 툴팁으로 병기한다. 한국어 이름 전체를 공식 게임 번역과 대조 완료했다고 주장하지 않는다.

수치 자동 연결이 없는 팩션은 `직접 입력` 표시를 붙인다. 보스, 엑시무스 고유 오라·저항, 적응형 피해 감소, 주변 오라, 특수 약점 부위, 특수 결속은 일반 적으로 가장하여 자동 계산하지 않는다. 방어층 파괴를 포함한 시간별 전투 전이는 기존 교전 엔진의 미지원 범위를 유지한다. 첫 타격과 고정 상태 TTK의 방어층 모델, 5초/10초 교전의 지원 범위는 서로 다르다.

원본 23건의 URL·개정·시각·SHA-256·본문은 `data/enemy-source-records.json`에 있다. 모듈 10개 전체 원본을 보존하지만 1,000여 원본 행 전체가 계산 대상인 것은 아니다. `tools/verify_enemy_sources.py`는 원격 Lua를 실행하지 않고 AST로 읽어 정규화한 31종의 내부 ID·팩션·기본 레벨·체력·실드·방어력·엑시무스 전용 기본 수치을 원본과 대조한다.

## 레벨 성장식

기준: [Enemy Level Scaling · revision 2795886](https://wiki.warframe.com/w/Enemy_Level_Scaling?oldid=2795886).

`q = 입력한 적 레벨 − 적 기본 레벨`, `f₁ = 1 + c₁qᵉ¹`, `f₂ = 1 + c₂qᵉ²`이다. `t = clamp((q−70)/10, 0, 1)`, `s = t²(3−2t)`로 보간하며, 위키에 적힌 binary32 연산 순서 `f₁ + (f₂−f₁) × s`를 보존한다. 부동소수점 소거를 바꾸는 양 끝점 치환이나 이중 정밀도 가중합으로 대체하지 않는다.

| 체력 성장 그룹 | c₁ | e₁ | c₂ | e₂ |
|---|---:|---:|---:|---:|
| 그리니어·스칼드라 | 0.015 | 2.12 | 10.7332 | 0.72 |
| 코퍼스 | 0.015 | 2.12 | 13.4165 | 0.55 |
| 인페스티드 | 0.0225 | 2.12 | 16.0998 | 0.72 |
| 커럽티드·아나키스트 | 0.015 | 2.1 | 10.7332 | 0.685 |
| 속삭임 | 0.015 | 2 | 10.7332 | 0.5 |
| 테크병 | 0.02 | 2.12 | 15.0998 | 0.7 |

실드는 코퍼스 `(0.02, 1.76, 2, 0.76)`, 테크병 `(0.02, 1.76, 3.5, 0.76)`, 커럽티드 `(0.02, 1.75, 2, 0.75)`를 사용한다. 방어력은 `(0.005, 1.75, 0.4, 0.75)`이다. 처음 생성되는 유방어 적의 방어력은 200~2,700, 무방어 적은 0이다. 공격으로 방어력을 깎은 뒤 200으로 올리는 처리는 하지 않는다.

## 난이도

- **일반:** 레벨 성장 수치 그대로 사용한다.
- **강철의 길:** 위키 최신 고정 원문 기준 체력·실드 ×2.5. 방어력에는 별도 배수를 곱하지 않는다. 입력 레벨은 게임의 표시 레벨이므로 +100을 다시 더하지 않는다. 원본: [The Steel Path · revision 2813195](https://wiki.warframe.com/w/The_Steel_Path?oldid=2813195).
- **빙주령:** [공식 Update 44.1.0](https://www.warframe.com/ko/patch-notes/pc/44-1-0)과 [The Icebind · revision 2817464](https://wiki.warframe.com/w/The_Icebind?oldid=2817464)의 Empowered Enemies를 연결했다. 증가량은 `200% + 100% × 분대 인원`, 기본 수치에 곱할 배율은 `3 + 분대 인원`이다. 1명 +300%/×4, 3명 +500%/×6, 6명 +800%/×9. 강철의 길 배수와 중첩하지 않는다.

빙주령 선택 시 999 미만 레벨은 999로 올린다. 이후 999 미만 입력은 오류로 표시한다. 분대 인원은 1~6명으로 설정한다. 미등장 팩션으로 변경하면 일반 난이도로 전환하고 빙주령을 비활성화한다.

**빙주령 방어력 확인:** 위키의 [실제 정보창 계산 코드 rev.2816353](https://wiki.warframe.com/w/MediaWiki:Gadget-enemyinfoboxslider.js?oldid=2816353)는 `base_armor *= (3 + player_count)` → 레벨 성장 → `min(armor,2700)` → `max(armor,200)` 순서다. 따라서 강화 후 2,700을 적용하는 기존 수치의 근거를 확보했으며 가정 표시를 제거했다. `tools/verify_enemy_sources.py`에서 보존한 코드의 배율·연산 순서를 별도로 검사한다. 기본 방어력을 사용하는 계산에도 강화된 기본값을 전달한다. 공식 패치 노트는 강화 비율을 확인하고, 위키 계산 코드는 상한의 적용 순서를 확인하는 역할로 구분한다.

Archaic Armor(고대 방어력) 등 특수 결속은 기본 Empowered Enemies 강화와 다르다. 공식 자료는 일반 방깎 차단과 타격당 최대 방어력 1% 감소를 설명하지만 정확한 초기 강화량을 제공하지 않는다. 이 버전은 해당 결속을 지원한다고 표시하지 않는다. Armor 문서의 예외적 2,700 초과 공식을 일반 빙주령에 임의 적용하지 않는다.

## 엑시무스

- 연결된 전용 기본값이 있는 27종에서 선택할 수 있다. 일반 적 기본값을 덮어쓰는 `EximusHealth`, `EximusShield`, `EximusArmor`, `EximusOverguard`를 원본 그대로 보존한다. 엑시무스 수치가 미연결된 러너·럼버링 프래그먼트·아나키스트 2종은 토글을 비활성화한다. 모든 특수 엑시무스 종류·출현 규칙을 지원한다는 뜻은 아니다.
- 체력·실드 추가 보정은 위키 정보창 코드의 `q = 표시 레벨 − 적 기본 레벨`을 사용한다. q=15/25/35/50/100 경계의 보정 계수는 1/1.25/2.5/4.5/6이다. 중간 구간은 위키의 선형식을 따른다.
- 체력 보정 기본값은 `max(기본 체력 × 1.1, c × (기본 체력+900) × 보정 계수)`이다. 실드나 방어력이 있으면 c=0.25, 둘 다 없으면 c=0.375. 실드는 `기본 실드 × max(1.1, 보정 계수)`이다. 이후 난이도 배율과 팩션 성장식을 적용한다.
- 오버가드는 [Enemy Level Scaling rev.2795886](https://wiki.warframe.com/w/Enemy_Level_Scaling?oldid=2795886)의 명시적 식에 따라 **적 기본 레벨과 관계없이 q=표시 레벨−1**, 기본 12를 사용한다. 하위식 `1+0.0015q⁴`, 상위식 `1+260q⁰·⁹`, 전환 q=45~50의 smoothstep 및 binary32 순서를 보존한다. 위키 정보창 JS의 구형 오버가드 계산이 개별 적 기본 레벨을 사용하는 부분은 이 명시적 설명과 충돌하므로 가져오지 않았다. 이 출처 우선순위를 기록한다.
- 강철의 길·빙주령의 체력/실드/방어력 배수를 오버가드에 곱하지 않는다. [Overguard rev.2814940](https://wiki.warframe.com/w/Overguard?oldid=2814940) 기준 같은 표시 레벨이면 일반 엑시무스 종류의 오버가드는 동일하다.
- 첫 타격에서는 오버가드에 방어력·바이러스 보너스를 적용하지 않고 자성 및 보이드 취약성을 적용한다. 오버가드 중 띄워짐·넘어짐은 CO 종류에서 제외한다. 냉기 4중첩 상한과 동결 불가는 기존 대상 모델을 유지한다.
- 고정 상태 TTK의 오버가드→실드→체력 경로와 시간별 상태 누적 교전은 구분한다. **오버가드·실드를 파괴하며 CO·버프가 변하는 5초/10초 전투 모델은 아직 미지원**이며 결과에 해당 제한을 표시한다. 엑시무스 고유 오라·배리어·에너지 흡수 등은 별도 모델이 없다.


## UI 변경과 검증

- 각 선택창 위에 팩션, 적, 교전 조건, 공격 방식, 스탠스 동작, 공격 시작 시 콤보 배수 이름을 표시한다.
- 콤보 선택은 `1× · 콤보 없음`, `12× · 콤보 누적 상태`처럼 의미를 보여 준다.
- 선택창 화살표는 텍스트 글리프 대신 고정 크기 벡터를 수직 중앙에 둔다. 상세 영역의 화살표는 오른쪽/아래로 회전하고 헤더 전체를 클릭할 수 있다.
- 프라이머 선택 시 상태 칩·중첩 설정을 표시하며 다른 교전 조건에서는 숨긴다. 무기 고급 효과는 기본 접힘이다.
- 적이나 파생 방어력에 호버하면 수식의 실제 방어층 항을 재계산해 강조한다.
- 레벨 입력이 비거나 유효 범위를 벗어나면 오류를 해당 영역에 표시하고 이전 결과를 지운다.
- 전체 계산 회귀 228개를 검증한다. 31종 × 7개 레벨 × 2개 난이도 경계 검사, 성장식 70·75·80 보간, SP 중복 레벨 금지, 빙주령 인원 배수, 저장 왕복 포함.
- UI 검사는 실제 WPF 컨트롤의 선택 이벤트·상태·좌표를 검사하며 사용자 마우스로 게임과 병행한 실측과는 구분한다. 최종 배포 EXE의 JSON 결과와 최소 1760×920, 125/150% 배율 이미지를 함께 제공한다.

## 장비 슬롯과 드래그

8개 모드 아래에 엑실러스·근접 아케인·조우 아케인 슬롯을 항상 표시한다. 앞의 두 슬롯은 장착·랭크·해제와 저장/복원을 연결하고, 엑실러스 극성 및 수용량을 반영한다. 근접 아케인 장착 시 가운데 발동 조건을 펼쳐 필요한 조건만 표시한다. 조우 부품 조립은 미구현이므로 조우 아케인은 자료 조회만 제공하고 일반 무기에 장착하지 못하게 한다.

드래그 중 카드는 한 번 독립 렌더링한 이미지를 76% 불투명도로 커서 옆에 표시한다. 새로 배치된 WPF 카드의 그리기 캐시가 빈 상태인 경우를 회귀 검사로 재현했다. 포인터를 누를 때 캡처하여 카드 바깥으로 빠르게 이동해도 시작 이벤트를 놓치지 않는다. 일반 WPF 이벤트 경로에서 이동·놓기·Esc·캡처 상실을 처리한다. 보관함은 드래그 해제 영역으로 강조한다. 창 비활성화·닫기에서도 원본 투명도와 캡처를 복원한다.
