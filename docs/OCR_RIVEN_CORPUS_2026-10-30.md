# 한국어 리벤 OCR 추가 학습·검증 · 2026-10-30

공개 한국어 리벤 카드 **45개**를 확보해 추가 학습과 검증을 진행했다. **40개 원본 이미지 / 19개 공개 게시글**에서 추출한 카드이며, 같은 원본의 전후 카드 등을 별개 원본으로 세지 않는다. 출처 URL·원본/카드 해시·정답·분할 정보는 `tests/fixtures/riven-public-corpus-20261030.json`에 기록한다. 공개 이미지 자체는 저장소와 앱에 재배포하지 않는다.

## 분할과 정답 검수

| 분할 | 카드 수 | 용도 |
| --- | ---: | --- |
| 학습 | 27 | 분류기 가중치 갱신·학습 표본 내 hard example mining |

동일 원본·게시글·캡처 묶음을 같은 split에 배치했다. 이전 공개 실패 12장은 학습·개발 자료로 전환했고 새로운 미학습 시험이라고 집계하지 않는다. 작성자가 올린 모든 이미지의 독립성까지 증명한 대규모 표본은 아니다.

원본을 확대해 정답을 재확인하면서 세 항목을 수정했다. 보어의 전기 **101.7 → 101.2**, 리디머의 치명타 피해 **91.3 → 97.3**, 아크손돌의 **+134.5 관통**을 음수 반동으로 잘못 적은 주석이다. 기존 결과 파일은 보존하고 수정된 동일 정답으로 이전·새 결과를 재채점했다. 수치 범위에 맞추기 위한 숫자 보정은 하지 않았다.

## 실제로 학습한 부분

기반은 [PaddleOCR의 한국어 PP-OCRv5 인식 모델](https://huggingface.co/PaddlePaddle/korean_PP-OCRv5_mobile_rec)이다. 기존 `korean-line-v5.onnx`와 동일한 backbone·SVTR 시퀀스 인코더를 보존하고, CTC 최종 분류기의 weight/bias 두 텐서만 역전파로 갱신했다. 모델 구조와 나머지 가중치는 변경하지 않았음을 비교했다. 처음부터 독자적으로 만든 범용 OCR이라고 주장하지 않는다.

- 실제 물리 글줄 155개: 학습 123개, 검증 32개.
- 원본 주석 crop과 실제 런타임 crop에 원색·반전·색상 마스크를 적용. 학습 실제 view 738개, 검증 view 192개.
- 학습용 숫자·옵션 조합을 합성한 1,400개 글줄. 앱의 기존 폰트 자산은 변경하지 않았다.
- 고정 특징 cache 총 2,330개. 최종 시험 11개 이미지는 특징 cache 생성에서도 열지 않는다.
- 선택 모델 `paddle-head4`, step 1,000. 검증의 옵션·숫자 오류, 학습 문자 오류, 검증 원문 문자 오류 순으로 선택했다.
- 검증 raw 글줄 **186/192 일치**, 문자 오류율 **0.3145%**. 나머지 여섯 문자는 커서에 가려진 `탄창 용량`의 `창`이며, 원본/런타임 crop의 세 view에서 반복된 동일 위치이다. 긴 옵션명의 유일한 한 글자 차이만 정규화한다. 두 글자 원소명이나 숫자를 추측하지 않는다.

모델 학습·내보내기 도구는 `tools/train_riven_ocr.py`에 보존한다. 기반 모델 SHA를 확인하고, `cache`는 train/validation만 사용하며, `export`는 최종 분류기 두 텐서 이외의 graph·가중치가 같은지 검사한다. 학습은 PyTorch를 사용했지만 앱은 **C#/.NET 8 + ONNX Runtime CPU**로 실행한다. Python·PyTorch·PaddlePaddle·CUDA를 클라이언트에 추가하지 않았다.

선택 모델:

```text
Assets/Ocr/riven-line.onnx
크기: 13,572,266 bytes
SHA-256: 6d23adfaf42579e3dfb172dc810032658bb1b602dc5f70ef6257901276de32e7
```

기존 `wfkor.traineddata`, `eng.traineddata`, 범용 `korean-line-v5.onnx`는 이번 재학습으로 변경하지 않았다. 학습한 작은 CRNN·추가 Tesseract 후보도 비교했으나 미학습 정확도가 떨어져 채택하지 않았다.

## 실행 경로와 자동 확정

1. MR 표식과 저비용 색상·기하 탐지로 카드 글자 영역을 찾는다. 타이머마다 전체 화면에 신경망 OCR을 실행하지 않는다.
2. 실제 글줄을 분리하고 원본의 색상 대비를 보존한 반전 이미지로 새 모델을 실행한다. 작은 글자의 획이 달라지지 않도록 학습과 실행의 bilinear 보간 좌표를 맞췄다.
3. 색상 마스크의 명칭 일치·신뢰도를 확인한다. 이는 같은 모델의 일관성 검사이며 독립적인 두 엔진의 투표라고 세지 않는다.
4. 각 원본 숫자 영역의 **값·부호·단위**를 별도 Tesseract 판독으로 교차 확인한다. 같은 고정 crop에서 확인하며 수치 범위로 누락된 숫자를 복원하지 않는다.
5. 빠른 경로가 불완전하면 기존의 원색·마스크·글줄 판독으로 넘어간다. 별도 관측에 없는 옵션을 붙이거나, 짧은 부분 합의로 이미 읽은 옵션을 버려 확정하지 않는다.
6. MR 표식을 찾지 못한 넓은 화면도 sparse locator가 옵션 영역을 찾은 후 bounded fast path를 사용한다. 전체 화면을 여러 번 읽는 느린 경로의 사용을 줄인다.

범용/추가 학습 PP-OCR은 backbone을 공유하므로 둘만의 일치로 독립 합의를 만들지 않는다. 자동 무기 종류는 정확한 제목을 우선하고, 불명확하면 가능한 종류를 유지한다. 센티넬·동반자 총기의 종류도 제목 사전에 포함한다.

**원문 인식과 현재 수율 유효성을 구분**한다. 과거 기질·랭크의 공개 카드는 원문을 정확히 읽어도 현재 기질 1.2의 수율에 맞지 않을 수 있다. 이런 카드는 숫자를 바꾸지 않고 수치 범위 확인을 요구하며, 현재 유효 옵션으로 자동 등급을 부여하지 않는다.

추적 영역은 테두리·사진·빛 효과가 아니라 실제 판독한 글자 범위를 따른다. 같은 카드의 테두리 애니메이션 때문에 반복해서 OCR을 다시 시작하는 현상을 저장 프레임 재생으로 검사했다.

## 정확도와 시간

공개 카드 45장의 원문 옵션 순서·종류·수치·부호가 모두 일치했다. 학습에 사용하지 않은 11장도 첫 평가에서 **11/11 일치**, 잘못된 자동 확정은 0개였다. 이후 시험 이미지의 반복 검사는 고정 회귀이며 새로운 독립 시험으로 세지 않는다.

이 합격 기준은 **무기 종류, 순서가 있는 옵션 키, 표시 수치와 부호**다. 무기의 전체 이름·임의로 생성되는 라틴어 리벤 접미사·사진 속 모든 문자를 완벽히 전사했다는 뜻은 아니다. 제목은 종류 판별의 근거로 사용하지만 제목 전체의 문자 정확도는 이번 45장 합격률에 포함하지 않았다.

수정된 정답으로 다시 채점한 이전 실행 결과는 **32/45**, 새 결과는 **45/45**다. 이전 최초 보고의 31/45와 차이가 나는 이유는 위 정답 주석 수정이다.

최종 독립 실행 파일 `1.0.0-rc.6-ocr.1`의 측정 결과다. Intel Core i7-10700KF, 논리 프로세서 16개, ONNX Runtime CPU를 사용했다. 다른 시각에 측정한 이전 결과와 비교하는 오프라인 검사이므로 실제 게임 중 프레임 영향이나 동일한 시스템 부하를 보장하는 A/B 실험은 아니다. OS 파일 cache를 비우지 않았다.

시간은 고정 카드 이미지의 탐지·OCR·교차 확인까지이며 게임 화면 캡처·오버레이 표시 지연을 포함하지 않는다. 최대 시간은 최종 프로세스의 첫 입력이었다. 실패한 이전 입력의 시간도 이전 분포에 포함했다.

실제 저장 전후 리벤 화면은 탐지와 두 카드 OCR을 함께 측정했다. 준비 0.463초, 첫 판독 2.915초, 반복 병렬 판독 세 번 **2.082~2.218초**, 순차 판독 세 번 **2.430~2.525초**였으며 모두 수치·부호가 일치했다. 이 값은 고정 카드 crop 한 장의 중앙값과 다른 측정이다.

## CPU·메모리와 실제 UI 검사

별도 데스크톱에서 200ms 간격으로 측정했다. CPU는 논리 프로세서 16개 전체를 100%로 환산한 평균이며, 메모리는 해당 단계 종료 시 working set이다.

| 상태 | 평균 CPU | Working set |
| --- | ---: | ---: |
| 모딩 화면 대기, 일정 숨김 | 0.068% | 283.0 MiB |
| 일정 화면 표시·초당 갱신 | 0.703% | 287.7 MiB |

두 카드 OCR 중 평균 CPU는 약 11%였다. 모델·native OCR context를 재사용해 반응 시간을 줄이며, 메모리가 OCR 사용 전 수준으로 즉시 내려가지는 않는다. 강제 GC·working set 비우기는 사용하지 않았다. 이 검사는 단기 프로파일이며 장시간 누수 검증을 대신하지 않는다.
