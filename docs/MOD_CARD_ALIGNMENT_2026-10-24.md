# 모드 카드 정렬과 다음 작업 — 2026-10-24

## 수정 범위

사용자가 제시한 주무기·보조무기 카드의 이름/장식선 겹침을 수정한다. 근접 카드의 배치 규칙을 공통 `ModCardLayout`과 `ModCardFace`로 옮겨 세 무기 유형에 함께 적용한다.

- 장착 카드 높이 88 DIP, 보관함 80 DIP. 이름은 각각 18/15 DIP, 줄 높이 24/20 DIP, 최대 두 줄로 표시한다.
- 카드 너비와 프레임 안쪽 선의 비율에 맞게 좌우 여백을 확보한다. 중앙으로 돌출된 아말감 장식에는 추가 여백을 준다.
- 코스트/극성과 이름 영역을 분리한다. 이름이 두 줄을 넘으면 말줄임하고 전체 이름과 효과는 툴팁에 유지한다. 보관함에서 효과 설명만으로 전체 이름을 덮어쓰던 문제도 수정했다.
- 호버와 키보드 초점은 외곽 강조만 바꾸고, 등급별 프레임 배경을 유지한다.
- 보관함의 열 수를 세 유형에서 같은 너비 규칙으로 결정한다. 검색 결과가 적어도 보관함 상단에 배치한다.
- 총기 드래그 미리보기도 동일한 이름/코스트 배치를 사용한다. 포르마가 반영된 실제 코스트를 복제하며 카드 높이로 유형을 추측하지 않는다.
- 기존 Ideal/ClearType 글자 렌더링과 계산 규칙은 유지한다.

## 검수 방법

`--mod-card-check`는 일반 잘림 진단에서 제외되는 말줄임 텍스트도 별도로 측정한다. 실제 카드 생성기를 사용해 이름과 코스트 영역이 160×104 프레임의 안쪽 선/아말감 장식을 침범하는지 검사한다. 좁은/보통/넓은 카드, 더잠실체·Pretendard·Wanted Sans, 다크/라이트, 시각 트리 DPI 100/125/150%를 포함한다. 주무기·보조무기는 1760×920과 2560×1080에서 긴 이름을 장착하고 보관함 두 줄과 가로 스크롤 여부도 확인한다. 검색 한 건의 위치는 UIA Value 패턴으로 실제 입력해 확인한다.

`--interaction-check`는 UIA Invoke/ExpandCollapse/SelectionItem을 통해 장착·해제·랭크·극성·코스트·아케인·정렬·하위 메뉴와 드래그를 검사한다. 전체 계산 회귀와 `--smoke`도 실행한다. 카드/상호작용 검사를 `tools/validate.ps1`에 추가하여 이후 Windows CI에서 함께 실행하도록 했다.

| 최종 검증 | 결과 |
|---|---|
| Release 빌드 | 경고 0 · 오류 0 |
| 계산 회귀 | 1,519개 통과 · 실패 0 |
| 카드 프레임·이름·검색 위치 | 2,606개 통과 · PNG 30개 |
| 실제 UI 조작 | 128개 통과 |
| 전체 UI smoke | 정상 종료 · 보고서 10개 통과 · 기하 기록 1개 · PNG 153개 |

최소 창의 주/보조 화면, 넓은 창, 긴 이름의 등급별 카드 이미지를 직접 열어 확인했다. 앱과 검사 프로그램의 계산 엔진 DLL SHA-256이 일치한다.

최종 결과와 실행 파일 해시는 `artifacts/mod-card-final-verification.json`에 기록한다. 렌더링 이미지는 확대율을 임의로 보정한 이미지가 아닌 WPF 시각 트리 DPI를 적용한 결과이며, 실제 서로 다른 DPI의 모니터 사이 이동 시험과 구분한다.

## UI 이후의 작업 순서

### 1. 최근 변경분을 묶은 배포 후보 검증

현재 로컬 프로젝트 버전은 `0.8.0-preview.2`이고, `DISTRIBUTION.md`에는 같은 버전의 기존 공개 배포가 기록되어 있다. 새 변경을 업데이트로 전달하려면 새 버전 번호로 분리해야 한다. 설치·업데이트·자동 시작 코드는 이미 있으므로 현재 변경분에 대한 설치 전이 검증이 다음 작업이다.

- 복구된 미커밋/미추적 변경을 보존한 상태에서 배포 대상 파일, 데이터·폰트 고지, 빌드 버전을 정리한다.
- 현재 계산/모딩/리벤/카드/UI/작업 복구 검사를 배포 후보 실행 파일에서 실행한다.
- 기존 버전 → 새 버전 업데이트 확인·다운로드·적용·재시작 후 주무기/보조무기/근접 빌드, 비교 기준, 미완성 리벤 입력이 유지되는지 검증한다. 엔진이 달라진 비교 결과를 최신 결과로 재사용하지 않는지도 확인한다.
- 알려진 근사는 결과의 근거·가정·영향과 함께 유지하고, 확정 규칙과 구분된 지원 목록을 배포 문서에 포함한다.
- 실제 서로 다른 DPI 모니터 전환, Windows 로그인 자동 실행, 게임 실행 자동 시작, 게임 병행 시 유휴 CPU/메모리·UI 응답은 별도의 환경 검증으로 마무리한다. 이번 카드 수정으로 이 항목까지 통과했다고 처리하지 않는다.
- 그 결과를 확인한 다음 새 설치 파일과 공개 업데이트를 준비한다. 이번 UI 작업에서는 설치 파일 생성·공개 게시를 실행하지 않는다.

### 2. 다음 신규 기능: 성유물 보상 인식과 시세 비교

기존 개발 명세의 우선순위에 따라 진행한다. 먼저 한국어 보상 화면 이미지에서 후보 4개와 품목 ID를 추출하고, 미인식/낮은 신뢰도에는 사용자가 수정할 수 있는 선택지를 제공한다. 그다음 Warframe.market 연동·가격/듀캇 비교·조회 시각/캐시/오프라인 표시를 추가한다. 실제 API 사양과 이용 조건은 착수할 때 공식 자료를 다시 확인한다. 화면 인식은 사용자가 요청한 순간/보상 화면에 제한하고 상시 전체 화면 폴링을 하지 않는다.

### 3. 마스터리 제작·랭작 계획

보유/숙련 장비, 재료, 제작 조건을 먼저 관리하고 제작 가능 장비와 다음 목표를 제시한다. 워프레임 어빌리티 전체와 익절티드 확장은 합의한 별도 후속 단계로 유지한다.

이 순서는 다음 작업의 제안이며, 성유물/마스터리 기능 구현 또는 새 공개 배포를 이번 카드 변경의 완료 항목으로 포함하지 않는다.
