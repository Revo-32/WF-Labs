# 장비 획득 방식·성유물 추천·자동인식 상태 UI

## 후속 수정: 구매 탭 추천순

- 원인: 구매 탭에도 전체 제작 추천의 획득 경로 버킷·부족 품목 수·크레딧 우선순위가 적용되어, 동일 마스터리의 36 P가 20 P보다 앞에 나올 수 있었다.
- 상점 플래티넘·유저 간 거래 탭은 별도 구매 추천 정렬을 사용한다. 현재 추가 마스터리 획득이 가능한 장비, MR 조건 충족, 마스터리 1,000점당 추가 구매비, 총 구매비 순이다. 동일 비용이면 시세 신선도·부족 품목 수·크레딧·제작시간·이름으로 안정적으로 정렬한다. 제작시간은 마지막 동률 처리에만 사용한다.
- 거래비는 예약과 보유분을 제외한 현재 계획의 추가 거래비다. 시세 누락·부분 합계는 0 P로 간주하지 않는다. 0 P는 모든 필요 비용이 확인된 경우만 인정한다. 상점은 거래비가 아닌 상점 표준가를 사용한다.
- 구매 외 탭의 기존 보유/제작/크레딧/파밍 추천 흐름을 유지한다. 목록에 추천 순번·1,000점당 비용 또는 추천 보류 이유를 표시하며 상세에도 같은 기준을 표시한다.
- Release 빌드 경고·오류 0. 전체 Core 검증 1,764개 통과·0개 실패. Core 부분 검수 69개 통과. 가격 역전·6,000점과 3,000점의 효율 비교·미확인 시세·MR 제한·0 P·병렬 제작시간·상점가/거래가 분리·가격 갱신 후 재정렬을 추가했다.
- 최종 실행 후보 UI Automation 117개 통과. 저장된 실제 계정 목록·가격을 읽기 전용으로 불러와 두 구매 탭의 정렬과 화면도 검증했다. 같은 3,000점의 거래 후보가 4/7/9/9/10/13 P 순서로 나타났다. 이는 저장 호가 검수이며 실시간 거래 가격을 보장하지 않는다.
- 공통 화면 `--smoke` 종료 코드 0, 153개 화면 렌더링 완료 (`artifacts/recommendation-ready-smoke`). 검수 전용 코드에 실제 저장 목록 검사를 추가한 최종 후보에서도 UI 검증을 별도로 완료했다.
- 로컬 후보 `artifacts/recommendation-verified-app/WFLabs.exe` (`0.11.0-preview.4`). UI 증거 `artifacts/recommendation-verified-ui`, 계산 검증 `artifacts/recommendation-order-core.log`. 공개 배포·업데이트 피드는 변경하지 않았다.

## 후속 수정: 탭 여백·구매 경로 분리

- 공통 NavigationItem 최소 높이를 40 DIP로 맞췄다. 상단/하위 메뉴의 글자-밑줄 여백은 100%에서 각각 11 DIP, 150%에서 각각 약 10.7 DIP다. 고정 글자 높이에 밑줄이 붙던 하위 탭을 수정했다.
- 기존 플래티넘 구매 탭은 상점 플래티넘 / 유저 간 거래로 분리했다. 게임 내 상점 표준가·구매 경로와 Warframe Market 게임 ID 연결을 독립적으로 판정한다. 시세 유무나 일반 자원 비용이 상점 구매 여부를 바꾸지 않는다.
- 유저 거래는 완성 장비뿐 아니라 설계도·주요 부품 거래도 포함한다. 부품 구매 후 추가 제작·파밍이 필요할 수 있음을 표시한다. 일반 자원을 살 수 있다는 이유만으로 장비를 거래 탭에 넣지 않는다. 상점·거래 경로가 모두 있는 장비는 두 탭 모두 표시한다.
- 목록·선택 상세도 현재 탭에 맞춰 상점 가격 / 거래 시세를 우선 표시한다. 다른 제작 경로와 비용은 아래에 유지한다. 상점 가격은 할인·쿠폰 제외 표준가이며 실시간 매장 조회값이 아니다.
- 실행 후보: `artifacts/acquisition-ready-app/WFLabs.exe`, `0.11.0-preview.3`. 공개 배포·업데이트 피드 미변경.
- 최종 후보 UI Automation 109개 통과. 다크/라이트, 1760×920 100% / 1280×720 DIP 150% 화면 직접 확인. 상점·거래 분리, 목록 가격 종류, 실제 글자-밑줄 간격을 검증했다.
- 전체 Core 검증 1,756개 통과·0개 실패 (`artifacts/acquisition-split-core.log`). 획득/인벤토리 Core 부분 검수 61개 통과. Release 빌드 경고·오류 0. 최종 후보 `--smoke` 종료 코드 0, 153개 화면 렌더링. 산출물: `artifacts/acquisition-ready-ui`, `artifacts/acquisition-ready-smoke`.
- 중간 smoke 실행이 출력 DLL을 잡고 있어 후속 빌드 복사가 실패했다. 해당 검수 프로세스임을 명령줄로 확인한 뒤 중단하고 빌드·최종 후보 UI/smoke 검수를 다시 완료했다. `acquisition-split-smoke` 및 `acquisition-split-ui-final`은 최종 증거로 사용하지 않는다.


## 변경한 사용 흐름

- 내 장비: 전체 요약 / 제작 중·보유 중 / 크레딧 설계도 / 파밍 필요 / 플래티넘 구매 / 기타 / 내 목표.
- 전체 요약은 마스터리 진행 그래프와 장비 목록을 전체 너비로 제공한다. 획득 탭에서는 요약 그래프를 접어 목록·획득 상세의 공간을 확보한다.
- 크레딧 설계도에서는 상점·도장 구매처를 추가로 고른다. 완성품 크레딧 구매도 포함한다고 표시한다.
- 본체 설계도만 크레딧으로 사고 섀시·시스템·뉴로옵틱스를 별도로 구해야 하면 파밍 필요로 분류한다. 일반 제작 자원이 부족한 것만으로 파밍 장비로 바꾸지 않는다.
- 플래티넘 구매는 대안 구매 경로다. 파밍 가능한 장비도 포함하며 구매가 필수라는 뜻이 아님을 화면에 명시한다. 따라서 이 탭의 개수는 다른 획득 탭과 중복될 수 있다.
- 성유물은 보상 인식·시세 / 성유물 추천으로 분리한다. 추천 목록과 보상 상세를 양쪽에 표시하고, 추천 조건·동기화·정련·분대 인원·가격 범위 기능을 유지한다.
- 장비 상세의 필요한 부품의 성유물 찾기, 내 목표의 추천 성유물 보기에서 목표를 전달해 해당 하위 탭으로 이동한다.

## 자동인식 상태와 조작

- 성유물의 상단 공통 상태 영역은 보상·추천 탭 전환과 본문 스크롤에도 유지된다.
- 리벤은 종류 선택 바로 아래에 자동인식 스위치와 실제 감지 상태를 표시한다. 오버레이 설정 창을 열 필요가 없다.
- 켜짐·화면 대기 / 화면 읽는 중 / 인식 완료 / 확인 필요 / 꺼짐을 구분한다. 색뿐 아니라 문구로도 상태를 알 수 있다.
- 기존 검정·노랑 테마의 얇은 강조선과 상태 점을 사용한다. 오류·확인 필요는 오류 색상을 따른다. 읽기 시작 시 상태 점만 짧게 전환하고 경량 모드에서는 모션을 생략한다. 반복 애니메이션·추가 화면 캡처 루프를 만들지 않는다.
- 리벤 메인 스위치와 열린 인식 설정 창의 자동인식 스위치는 양방향 동기화한다. 기존 설정 저장·감지 시작/취소 경로를 그대로 사용한다.
