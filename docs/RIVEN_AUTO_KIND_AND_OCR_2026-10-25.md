# 리벤 자동 종류 판별과 OCR 경로 개선 · 2026-10-25

사용자가 보고한 독성→SM 오인식, 소총 리벤을 근접으로 계산하는 문제,
실전 4.6초 이상 지연을 대상으로 수정했다. 학습 모델의 가중치는 기존
`wfkor`를 사용한다. 이번 변경은 전처리·언어 선택·영역 탐지·종류 판별·엔진
재사용이며, 새 실패 화면을 다시 학습시킨 결과로 표현하지 않는다.

## 자동 종류 판별

- 기본 선택은 **자동 판별**이다. 이전 설정 파일의 `Kind=Melee`도 새
  `DetectKind` 항목이 없으면 자동 판별로 읽는다.
- 모딩/리벤 작업실의 현재 탭으로 화면 인식 종류를 덮어쓰지 않는다.
- 해당 카드 근처 제목의 정확한 무기 이름을 기존 자료의 한국어/영어
  이름과 연결한다. 무작위 접미사는 종류 판별에 필요하지 않다.
- 제목이 불확실하면 근접·소총·산탄총·권총의 옵션 이름, 단위, 양음옵 구성,
  선택 랭크의 전체 수치 범위를 각각 검증한다. 하나의 종류만 유효할 때 확정한다.
- 예: 멀티샷 121%, 치확 208.4%, 반동 +53.3%는 소총이다. 양수 반동은
  불리한 음옵으로 해석한다. 숫자나 부호를 범위에 맞춰 수정하지 않는다.
- 여러 종류가 동시에 유효하면 등급·접합 예측을 보류하고 종류 선택을
  표시한다. 단일 무기 이름과 수치가 충돌하면 다른 종류로 갈아 끼우지 않는다.
- 리벤 랭크는 기존 설정값이다. `최대 랭크 보기`를 켠 게임 화면의 기본값은 8.
  MR 숫자는 리벤 랭크로 사용하지 않는다.

## OCR과 MR 기준점

- 한국어 학습 모델을 첫 판독에 사용한다. 혼합 모델을 매 줄 무조건 함께
  읽던 경로를 제거했다. 숫자가 제대로 읽히지 않을 때만 영어 수치 판독을
  호출한다. 일부 타이트한 가져오기 이미지에서 줄 경계를 잃는 경우에만
  캐시된 혼합 언어 판독을 추가로 한 번 시도한다.
- 네이티브 엔진은 직렬 게이트 안에서 재사용한다. 변형마다 한국어·혼합·영어
  모델을 새로 만드는 작업을 제거했다. 사용하지 않는 보조 모델은 로드하지 않는다.
- `MR`은 전체 화면 OCR로 찾지 않는다. 한국어와 독립된 작은 M/R 글리프
  형상, 두 글자의 상대 위치, 어두운 하단 띠와 긴 구분선을 함께 검사한다.
- 기준점 탐지에는 별도 OCR 모델 호출이 없다. 읽기 요청 때만 실행하고
  기존 750ms 작은 샘플 감지 루프에는 추가하지 않았다. CPU 작업은 작업자 스레드에서 실행한다.
- MR 크기를 이용해 위쪽 제목·옵션 영역을 추정한다. 작은 카드와 확대 카드의
  장식/긴 문장 넘침이 다르므로 좁은 영역과 여백을 둔 영역을 구분한다.
- 좁은 영역에서 확인하지 못하면 대체 영역, 기존 전체 화면 경로 순서로
  돌아간다. 픽셀 절삭으로 마지막 글줄이 달라지지 않도록 crop 크기를 올림한다.
- MR이 가려짐, 작은 글자, 전환 중, 새 UI 변형에서는 기준점이 없을 수 있다.
  모든 해상도에서 항상 찾는다고 보장하지 않는다. MR만으로 분석을 시작하지도 않는다.
- 각 옵션의 키·수치·부호·단위가 서로 다른 판독 두 번에 나타나야 자동 확정한다.
  누락 수치 추론이나 범위에 맞춘 숫자 수선은 하지 않는다.
- 검증된 카드의 편집 상자는 정규화된 옵션을 표시한다. 이름 접미사와 장식의
  OCR 잡음은 교정 입력란에 섞지 않으며 원본 판독은 진단 결과에 남긴다.

## 저장 화면 성능 비교

`artifacts/riven-auto-kind-2026-10-25/old-binary-comparison/results.json`과
`final-performance-rounded/results.json`. 동일한 저장 화면 여섯 개,
탐지·영역 선택·OCR·교차 확인을 포함한다. 네트워크/게임 전환 시간은 포함하지 않는다.
이전 실행 파일과 수정 실행 파일은 별도 프로세스이며 각 첫 항목은 모델 로드를 포함한다.
게임을 실행한 상태의 새 실전 지연 측정으로 간주하지 않는다.

| 저장 화면 | 이전 | 수정 | 수치·부호·종류 확인 |
|---|---:|---:|---|
| 인노뎀, MR 가려진 화면 | 3.08초 | 1.91초 | 일치 |
| 히루도 | 2.76초 | 0.53초 | 일치 |
| 팽 | 5.61초 | 0.87초 | 일치 |
| 시암 | 8.08초 | 1.21초 | 일치 |
| 새 울프 슬레지 카드 | 9.53초, 확인 실패 | 0.92초 | 전기 88.4 / 독성 79.6 / 치확 155.9 |
| 인노뎀, 배경 애니메이션 실전 캡처 | 2.78초 | 0.86초 | 네 옵션·음옵 일치 |

MR 형상 탐지 자체의 측정은 약 4~37ms였다. 단일 실행 표본이며 실전 P95가 아니다.
실전 자동 표시에는 작은 샘플의 안정화 대기와 화면 캡처 시간도 더해진다.

## 다른 한국어 엔진과의 비교

실험은 `E:\CODEX\Workspaces\WFLabsOcrEngineComparison`에 격리했다.
PaddlePaddle 3.3.1 CPU, 공식 `PaddlePaddle/korean_PP-OCRv5_mobile_rec`,
로컬 추론 두 스레드로 비교했다. 앱에 Paddle 런타임/모델을 배포하지는 않았다.

기존 학습에서 분리한 동일 test 82글줄의 완전 일치:

| 글줄 | wfkor | 한국어 PP-OCRv5 |
|---|---:|---:|
| 전체 82개 | 78 | 73 |
| 실제 게임 화면 7개 | 6 | 7 |

전체 CER는 각각 약 0.49%, 1.21%. 실전 7개만으로 우열을 일반화하지 않는다.
Paddle 글줄 처리 평균 약 120ms는 이미 잘린 글줄의 CPU 추론이며 카드 전체의
탐지/파싱/교차 확인을 포함한 시간이 아니다. 새 울프 슬레지의 타이트한
네 줄에서도 별도로 비교했으며, 아이콘·여백의 영향을 받으므로 이 결과를
완전한 엔진 교체 검증으로 표현하지 않는다.

재현 도구: `tools/ocr_engine_comparison.py`. 모델 출처/해시는 결과 JSON에 기록한다.
근거: [Tesseract 지원 언어](https://tesseract-ocr.github.io/tessdoc/Data-Files-in-different-versions.html),
[Tesseract 입력 품질](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html),
[PaddleOCR 공식 한국어 모델](https://huggingface.co/PaddlePaddle/korean_PP-OCRv5_mobile_rec).

## 추가 자료와 범위

사용자가 제공한 새 울프 슬레지, 리벤 목록, 일반 모딩 화면을 회귀 사례로
추가했다. 목록/모딩 화면은 자동 분석이 시작되지 않아야 하는 음성 사례다.
그 두 화면의 OCR 출력을 정답으로 삼아 자동 학습하지 않았다.

자료 경로는 `tests/fixtures/ocr-benchmark.json`에 고정한다. 사용자 스크린샷은
기존 방식처럼 로컬 `artifacts`에 두며 앱 패키지에는 포함하지 않는다.
이번 검수는 저장 화면과 비공개 Win32 데스크톱의 UI 검사다. 사용자가 종료한
실제 WF Labs는 재실행하지 않고, 게임 입력·포커스도 변경하지 않는다.
