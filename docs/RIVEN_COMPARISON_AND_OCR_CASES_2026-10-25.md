# 리벤 두 카드 비교와 실전 추가 사례 · 2026-10-25

이번 기록은 `RIVEN_AUTO_KIND_AND_OCR_2026-10-25.md` 이후 변경이다.
이전 기록의 Paddle 모델 미내장 상태와 구별한다. 이번에는 한국어 PP-OCRv5
보조 인식 모델을 실제 클라이언트에 포함했다. 사용자 스크린샷으로 이 모델을
재학습한 것은 아니다.

## 두 카드 오버레이

- 두 카드일 때 왼쪽 창을 기본 360→720 DIP로 확장한다. 화면 너비의 42%를
  상한으로 둔다. 같은 종류의 옵션을 같은 행에 두고 좌우 수치·양음옵·품질·등급·
  최소~최대 범위를 함께 표시한다. 없는 옵션은 `—`로 구분한다.
- 오른쪽에는 왼쪽 카드와 오른쪽 카드의 접합 레시피 및 부족한 재료를 각각
  표시한다. 서로 다른 카드의 재료를 합쳐 접합할 수 있다고 계산하지 않는다.
- 한 카드로 돌아오면 기존 너비와 단일 수율/접합 배치로 복귀한다.
- HWND를 재생성하지 않는다. 카드 개수가 바뀔 때만 짧게 내용을 드러내며,
  경량 모드와 Windows 모션 설정을 따른다. 같은 카드 재확인이나 커서 이동에는
  이 효과를 실행하지 않는다.
- 기존 비활성·클릭 통과·위치 변경 생략을 유지한다. 높이는 화면의 68% 이내로
  제한하고 배치의 아래쪽이 85%를 넘지 않게 하여 하단 쿠바/선택 영역을 비운다.
- 실제 옵션 영역과의 사이 공간이 충분하면 비교 너비를 조금 줄여 중앙 영역의
  겹침을 피한다. 모든 게임 UI 배율에서 원본 카드가 전혀 가려지지 않는다고
  보장하는 배치는 아니다. 실제 순환 화면 전체의 종단 검증은 별도다.

네 카드 모두 종류 자동 판별과 모든 수치·부호가 맞는지 확인한다. 태양과 달·타츠는
근접, 콤·스트런은 산탄총이다. 제목의 라틴 접미사 인식 결과는 분석 정답으로
요구하지 않는다. 태양과 달의 별칭 근거는 제공받은 게임 화면이며 기존 Public
Export 원문과 별개의 출처로 `data/riven-ocr-ko-evidence.json`에 기록했다.

## 판독 변경

- 옵션 뒤의 장식 문자와 숫자 앞의 프레임 잡음을 제거할 때는 완전히 일치하는
  한국어 옵션 이름만 허용한다. 숫자·부호·단위 문자열은 보존한다. `앵기`를
  임의로 `냉기`로, `xl.4`를 `x1.4`로 치환하지 않는다.
- 첫 판독부터 흰색 잠금/접합 옵션을 포함해 보라색 전용 재시도 후에야 흰색
  옵션을 발견하던 지연을 줄였다.
- 흰색 프레임 때문에 첫 줄이 빠지는 경우에는 보라색 전용 판독을 별도 근거로
  추가한다. 실제로 읽힌 첫 옵션의 경계를 복구하며 사진 영역을 무작정 넓히거나
  서로 다른 판독의 수치를 임의로 조립하지 않는다.
- 무기 제목에서 한 글자 이름 `콤`도 연결한다. `콤보`를 `콤`으로 판정하지 않도록
  경계를 검사한다. 이름의 줄바꿈을 연결하고, 뒤쪽 라틴 접미사의 `%` 잡음 때문에
  정확한 한국어 무기명까지 버리지 않는다.
- 제목을 못 읽을 때는 가까운 제목 글줄만 별도로 인식한다. 확정하지 못한
  옵션 행에는 한국어 PP-OCRv5 보조 판독을 사용한다. 전체 화면에 새 신경망
  탐지기를 상시 실행하지 않는다.
- 보조 모델은 CTC 문자별 점수로 양 끝의 낮은 신뢰 잡음만 제거한다. 내부 숫자를
  바꾸지 않는다. 유효한 옵션·범위 및 다른 판독과의 일치 검증을 그대로 거친다.
- 팩션 배율을 별도 영어 판독으로 읽는 경우는 실제 읽은 `x1.4` 문자열을 사용한다.
  모델 신뢰 점수를 만들어 붙이지 않는다. 동일한 영어 판독을 두 개의 독립 근거로
  복제하지 않는다.
- 게임에서 표시할 수 없는 두 자리 소수 `92.79`는 유효한 한 자리 수치의 근거나
  반복된 유효 수치 충돌로 세지 않는다. `92.7`과 `92.8`이 각각 반복되면 기존처럼
  자동 확정을 거부한다. `92.79`를 잘라 `92.7`로 만들지는 않는다.

## MR 두 개를 발견한 경우

실제 카드 두 장을 합성 배치한 시험에서 Tesseract가 같은 높이의 두 카드 글줄을
한 줄로 합쳐 한쪽만 반환하는 문제가 재현됐다. 기존 큰 간격의 시험 카드만으로는
확인하지 못했던 경우다.

MR 기준점 두 개를 찾으면 카드 사이 중앙선을 경계로 영역을 분리하고 각각
판독한다. 좌우 정렬과 전체 화면 좌표를 보존하며, 한쪽에 아무 옵션도 못 읽어도
그 위치를 미확정 카드로 유지한다. 자동 게임 캡처와 수동 이미지 입력에 모두
연결했다. MR이 없는 경우는 기존 영역 탐지 경로를 사용한다.

순환 횟수가 없는 카드에서는 MR이 가운데에 온다. 이 경우 MR을 카드의 왼쪽
끝이라고 가정하지 않고 실제 하단 구분선을 양쪽으로 추적해 범위를 잡는다.
태양과 달·타츠 두 카드의 중앙 MR 합성 배치도 전체/자동 경로로 추가 검증했다.

추가 합성 장면은 원본 콤/스트런 카드의 숫자를 수정하지 않고 1920×1080 검은
캔버스에 나란히 배치했다. 다른 무기의 카드로 만든 배치 시험이며 **실제 게임의
순환 전후 화면으로 표시하지 않는다.** 위치·원본·합성 여부는
`artifacts/riven-comparison-2026-10-25/two-real-crops.source.json`에 기록했다.

## 모델과 자원 사용

- 원 모델: PaddlePaddle/PaddleOCR `korean_PP-OCRv5_mobile_rec`.
- 변환 배포: RapidAI/RapidOCR `v3.9.2` 한국어 ONNX, 약 13.5MB.
- SHA-256: `cd6e2ea50f6943ca7271eb8c56a877a5a90720b7047fe9c41a2e541a25773c9b`.
- 실행: Microsoft.ML.OnnxRuntime 1.22.1, CPU 두 스레드, 유휴 회전 비활성.
  GPU·Python·PaddlePaddle 런타임은 클라이언트에 포함하지 않는다.
- 실제 카드 후보가 처음 잡히면 기존 화면 안정화 대기 중에 모델을 한 번만
  준비한다. 준비에는 빈 글줄을 사용한다. 새 화면 캡처나 게임 입력은 없다.
- 텐서 입력·출력은 연속 버퍼로 접근해 문자마다 다차원 인덱스 배열을 할당하지
  않게 했다. 숫자·부호 판정 결과는 동일하다.
- 원본 모델 URL, 라이선스, 해시 및 자체 추가 학습 여부는
  `Assets/Ocr/korean-line-v5.model.json`에 보존한다. PaddleOCR/RapidOCR Apache-2.0,
  ONNX Runtime MIT 및 전체 제3자 고지도 동봉한다.
