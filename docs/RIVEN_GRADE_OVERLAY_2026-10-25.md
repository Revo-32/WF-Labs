# 리벤 접합 경로·수치 등급 오버레이 검수

## 표시 기준

- F / C / B / A / S / SS / SSS는 WF Labs 자체 수치 품질 구간이다. 게임 공식 등급, 획득 확률, DPS·빌드 점수가 아니다.
- 양옵은 현재 구성·랭크에서 최솟값부터 최댓값까지의 위치를 사용한다. 음옵은 `1 - 범위 내 위치`로 바꿔 페널티가 작을수록 좋은 등급을 표시한다. 표시 백분율·막대·배지의 방향도 일치한다.
- 구간: F 0–20% 미만 / C 20–40% 미만 / B 40–60% 미만 / A 60–80% 미만 / S 80–90% 미만 / SS 90–97% 미만 / SSS 97–100%.
- 색상: F 회색 / C 은색 / B 민트 / A 파랑 / S 금색 / SS 주황 / SSS 보라. 문자 배지를 함께 사용해 색상만으로 구분하지 않는다.
- S 이상은 단계별로 테두리·정적인 은은한 빛을 강조한다. 글자는 효과의 시각 트리 밖에 두어 흐려지지 않게 했다. 반복 점멸·펄스는 없으며 경량 모드에서는 빛 효과를 생략한다.

## 접합

- 왼쪽 단일 카드 패널은 옵션 품질, 오른쪽은 접합 경로에 집중한다. 순환 전후 두 카드가 있으면 각 패널이 해당 카드의 수치·접합을 표시한다.
- `지금 접합 가능`은 실제 보유한 두 재료 옵션만 사용한다. 기존 접합 엔진의 계승 수치·반올림 구간을 등급 구간에 그대로 연결한다.
- `옵션 변경 후 가능`은 보유한 재료 한 개와 부족한 재료 한 개를 연결한다. 없는 재료의 수치를 만들어내지 않는다.
- 미래 경로의 등급은 **보유 옵션의 정규화 수율을 유지하고 부족한 옵션을 얻는다는 조건**에서의 범위다. 재순환 시 항상 유지되거나 결과가 보장된다는 뜻이 아니다. UI에 해당 가정을 표시한다.
- 접합 계승은 원래 수율을 사용한다. 음옵 품질 등급을 위해 뒤집은 값을 접합 계승에 넣지 않는다.
- 실제 인노뎀 카드: 현재 접합 0가지. 상태 확률 + 근접 피해 필요 → 상태이상 피해, 화염 + 독성 필요 → 가스, 화염 + 전기 필요 → 방사능, 화염 + 냉기 필요 → 폭발의 4경로를 표시한다.
- 조합은 기존 엔진의 [공식 44.1.0 패치 자료](https://www.warframe.com/en/patch-notes/pc/44-1-0) 기반 표를 재사용한다. 무기 종류별 지원 여부를 유지하며 이미 접합된 카드의 추가 접합은 예측하지 않는다.

## 자동 감지와 다른 오버레이 간섭

- 초기 실패 당시 이전 실행 파일의 프로세스가 계속 살아 있어 수정본 실행이 단일 인스턴스 처리로 기존 앱에 전달되고 있었다. 설정 JSON을 보존하고 정상 종료한 뒤 수정본을 실행했다.
- 이후 실제 자동 인식에서 4옵션과 좌우 패널을 확인했다. 사용자는 패널이 표시된다고 확인했다.
- Discord 번쩍임은 WF Labs 종료 뒤 멈췄다는 사용자 확인을 받았다. 원인을 단일 API로 확정하지 않는다. 반복적인 최상위 창 순서 재설정과 layered window 포함 캡처가 간섭할 가능성을 제거했다.
- 위치 추적은 변화가 없으면 네이티브 호출 0회. 이동 때도 `SWP_NOZORDER | SWP_NOACTIVATE | SWP_NOOWNERZORDER`를 사용한다. 최초 WPF Topmost 지정만 유지한다.
- 화면 캡처는 게임 client DC에서 SRCCOPY만 사용한다. CAPTUREBLT를 제거했다. 게임에 주입된 제3자 오버레이까지 모두 사라진다고 보장하지 않는다.
- API 근거: [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos), [BitBlt](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-bitblt), [GetDC](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdc).
- 수정 후 짧은 실제 자동 인식 검사에서 3.3초 및 좌우 창 표시를 기록했다. Discord 번쩍임이 완전히 사라졌다는 별도 사용자 확인과 장시간 동시 사용 검증은 아직 없다. 마지막 등급 UI는 저장된 실제 카드·격리 데스크톱에서 검증한다.

## 검증 기록

- 집중 Core 검사: 51개 통과. 등급 경계·음옵·즉시 접합 수치 계승·실제 카드의 4개 미래 경로·소총/산탄총/권총 경로 검증.
- 전체 Core 1,581개 통과, 실패 0개. 로그: `artifacts/riven-grade-2026-10-25-core.log`.
- 전체 WPF smoke 통과(`smoke/ui-check.json`: passed true, 종료 코드 0). 이 검사는 등급 연결 빌드에서 실행했고, 이후 오버레이의 중복 정보 제거·배지 글자 분리·두 카드 압축은 최종 빌드의 아래 48개 UI 검사로 재검증했다.
- 최종 오버레이 UI 48개 통과. 실제 인노뎀 4옵션 OCR, 단일/두 카드, FHD 100%/150% 배치, 등급·음옵 표시 방향, 누락 재료 경로, 교정·가져오기 Automation 동작, 120회 정지 위치 갱신 시 네이티브 호출 생략·이동 시 다른 최상위 창 순서 보존 검사 포함.
- 최종 좌우 카드와 150% 렌더링 PNG를 직접 열어 확인했다. 단일 카드 왼쪽의 중복 접합 목록을 없애 글자 크기를 확보했고, 두 카드 상태는 범위를 옵션명 옆으로 합쳐 공간을 줄였다. 배지의 글자를 빛 효과 밖으로 분리했다.
- UI 검사는 별도 Win32 데스크톱에서 수행한다. 사용자 화면 전환이나 게임 입력은 하지 않는다. 실제 게임 순환 버튼을 누르는 자동화도 하지 않는다.
- 이전 간섭 수정 검증: `artifacts/riven-passive-2026-10-25/` (Core 1575개, UI 45개, 실제 제한 캡처 및 자동 인식 로그).
- 최종 등급 검증: `artifacts/riven-grade-2026-10-25/`.
