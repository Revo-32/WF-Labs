# WF Labs 0.10.0-preview.1 릴리즈 준비

2026-10-26 KST. Windows x64·.NET 8.0.424/런타임 8.0.30·Velopack 1.2.161을 사용한다. 기존 저장소의 미커밋 작업과 이력을 보존하기 위해 별도 `release/0.10.0-preview.1` 작업 트리에 소스를 복사해 준비했다. 자체 코드는 공개 열람용이며 타사 데이터·폰트·모델의 원본 조건은 유지한다.

## 배포 구성

`builds/WF-Labs-0.10.0-preview.1/`에 설치 EXE, Portable ZIP, full.nupkg, feed·자산 목록·SHA256SUMS를 생성한다. `release-config.json`은 공개 저장소 `https://github.com/Revo-32/WF-Labs`와 미리보기 채널에 연결한다. .NET 런타임과 시작 도우미를 포함하며 설치 프로그램은 OCR의 `vcredist143-x64` 의존성을 확인한다. 실제 사용자 설치에는 적용하지 않는다.

공개 GitHub 릴리즈 초안은 설치본의 익명 업데이트 목록에 노출되지 않는다. 이 문서의 준비 완료와 공개 배포를 구분하며 공개 전에는 기존 0.9.0-preview.1이 온라인 최신 버전이다.

## 검수 원칙

로컬 설치 전이는 별도 `WFLabs.Verify` 식별자로 `0.9.0-qa.10 → 0.10.0-qa.2`를 확인한다. 설치·다운로드·적용·재시작·빌드와 리벤 복원·제거 뒤 실제 사용자 자동 시작 항목·설정·작업 파일이 그대로인지 대조한다. 전환하지 않는 별도 Windows 데스크톱을 사용한다.

계산 검사는 배포 패키지의 Core DLL로 실행한다. 패키징의 버전 속성과 검사 실행기의 참조 버전을 맞춘다. 실제 UI 검사는 배포 앱 자체로 진행하며 소스 빌드 결과나 과거 검수를 새 실행본의 결과로 대체하지 않는다.

## 한계

실제 게임과 병행한 성능, 물리 모니터 이동·로그인 전이, 모든 한국어 화면의 OCR 정확도, 실제 인벤토리 연속 동기화는 이번 릴리즈 준비가 보증하는 범위가 아니다. OCR 실패·시세 지연·미확인 및 예상 자료는 앱에 표시한다. Authenticode 인증서는 없어 설치 파일은 서명하지 않는다.

## 반복 실패 알림 방지

PR과 같은 브랜치의 수동 검증은 `windows-<head branch>` 그룹을 공유해 중복 실행을 취소한다. README·GitHub 표지/스크린샷·과거 기록만 변경하는 push/PR은 전체 Windows 앱 검증 대상에서 제외한다. 앱 소스·데이터·계산 검사·패키징·포함 라이선스/고지 변경은 기존 검증을 실행한다. 검증 단계 삭제, 오류 무시, 사용자 GitHub 알림 설정 변경은 하지 않았다. 실행 조건은 actionlint 1.7.12로 검증했다.

## 준비 중 발견한 문제

- 구버전 리벤 코스트는 base drain에서 현재 랭크를 포함한 표시 코스트로 정상 변환됐다. 기존 QA의 JSON 완전 일치 조건이 이 변환을 누락으로 오인해, 변환된 표현과 나머지 모든 초안·세션 필드를 비교하도록 고쳤다. 제품의 입력 손실을 수정한 것으로 보고하지 않는다.
- 실제 합성 FHD 두 보상에서 작은 글자 상자의 높이가 낱말 간격 기준을 줄여 한 보상이 여러 칸으로 나뉘었다. 줄의 대표 글자 높이를 사용하도록 수정했다. 별도 보상 간 물리 간격과 자동 확정의 교차 근거 기준은 유지했다. 이후 1~4보상·줄바꿈·수정 흐름 73개 검사를 통과했다.
- 주·보조무기 랭크 하위 메뉴에서 카드를 재생성하면 이전 ContextMenu가 열린 채 남을 수 있었다. 항목 실행 시 이전 메뉴를 먼저 닫고 랭크·극성·해제·리벤 편집을 적용하도록 수정했다. 실제 UIA 조작으로 닫힘과 수치 변경을 확인했다.
- 격리 검수 도구의 절대 경로 결합과 성공 뒤 이전 LASTEXITCODE가 남는 문제를 고쳤다. CI에서는 로컬 SDK 경로가 없을 때 global.json으로 설치한 .NET 8을 사용하며 모든 WPF 검사를 별도 데스크톱에서 실행한다.
- 패키지의 Core 버전 0.10.0과 검사 실행기의 기본 참조 버전 1.0.0이 달랐던 첫 시도는 검사 실행기도 같은 버전으로 빌드해 수정했다. 이후 배포 Core DLL로 1,707개를 통과했다.

초기 실패 산출물은 로컬 artifacts의 `release-validation`, `release-installer`, `release-core-first-attempt.log`에 보존했다. 후속 통과 결과와 구분한다.

첫 GitHub Windows CI는 계산 1,707개를 통과했으나 1024×768 가상 데스크톱의 최대 추적 크기가 설정 창을 1044px로 줄여, 1100px 검수 콘텐츠가 창 경계를 넘었다. MainWindow에만 적용하던 검수 창 크기 보장을 실제 표시 중인 모든 Window의 콘텐츠로 확장했고, 설정 창의 실제 Window 크기도 요청 크기와 대조한다. 제품 UI를 작게 줄이거나 경계 검사 허용치를 완화하지 않았다. 첫 기록은 [40255008875](https://github.com/Revo-32/WF-Labs/actions/runs/40255008875)에 있다.

두 번째 CI는 설정 창과 카드 검사를 통과했으나 첫 전체 렌더링 전 상호작용 검사에서 모니터 작업 영역 정책이 검수 창 최소 크기를 다시 줄였다. 비대화형 검수 데스크톱에서만 실제 모니터 작업 영역 제한을 분리하고 Loaded 시 native 크기를 명시한다. 일반 실행과 실제 모니터 이동 검사는 기존 정책을 유지한다. 검사 기준인 보관함 두 줄과 실제 공간을 줄이지 않았다. 두 번째 기록은 [40255806501](https://github.com/Revo-32/WF-Labs/actions/runs/40255806501)에 있다.
