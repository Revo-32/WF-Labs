# 총기 연결 수정과 명시적 근사 모델 — 2026-10-24

사용자의 최신 지시: 자료가 없어도 유사하게 구현할 수 있으면 구현하고 근사임을 명시한다. 확정 규칙과 근사 가정은 같은 종류의 검증을 통과했다고 표시하지 않는다.

## 확정된 연결 수정

- 팬타즈마/프라임 빔 시작 피해 15%, 0.6초 상승·정지 후 0.8초 유지/2초 감소. 탄약 소비 0.5/틱 유지.
- 고정 원문에 상승 규칙이 있는 28종 빔을 전수 대조했다. 팬타즈마 외 16종의 초기 피해(25~45%)와 바스무 보조 빔의 상승 시간(0.5초)을 수정했다. `tools/audit_ranged_beams.py`는 출처 해시와 정규화 수치의 일치를 재검사한다.
- 일반 팬타즈마의 멀티샷 모드는 기본 6이 아니라 5를 기준으로 증가: Hell's Chamber 120% → 12개. 프라임 페이지에는 해당 예외가 없어 프라임에 이 예외를 무단 복사하지 않는다.
- 일반형 충전 초당 11발·연사 모드의 충전 속도 미적용·탄창 증가에 따른 충전 연장·잔탄 충전·무한 탄약에서도 탄창 한도 적용.
- 본탄 직격 → 본탄 폭발, 본탄당 유도 자탄 5개 → 각각 직격·폭발. 멀티샷은 본탄 수에 적용하며 충전량을 자탄 수에 곱하지 않는다. 충전량은 발사 시점에 보존하여 재장전 후 도착한 자탄에도 유지한다.
- 각 공격의 독립 상태·강제 Impact/Stagger, 방사 피해의 약점 제외, 자탄 직격의 multiplicative CO를 기존 공격별 브라켓에 연결한다.
- 코모렉스 3.5배 사격을 별도 발사 동작으로 추가했다. IPS +100%는 물리 모드에 가산하고 원소·상태 씨드의 기본 피해97은 유지한다. 연사 -75%는 연사 모드에 가산하며 캐논네이드 잠금은 이를 제거한다. 관통은 마지막 대상에서만 폭발한다. 2배 조준의 관통2m·탄약 변환100%·폭발의 범위 모드 제외를 연결했다. 폭발 출력의 본문/모듈 상충은 아래 근사 표에 명시한다.

## 근사 사용 방식

- 새 모딩 화면에서는 **미기재 규칙은 근사 계산**이 기본으로 켜져 있다. 기존 저장 파일의 명시된 조건·근사 사용 여부는 보존한다.
- 직접 지정한 값이 항상 우선한다. 근사 모드를 꺼도 확정된 계산 규칙은 유지된다.
- 결과 상단의 **근사 포함** 아래에서 적용 값·근거·피해/DPS/TTK 영향 범위를 펼쳐 볼 수 있다. 런타임에만 발생하는 경계 조건은 결과 Notes와 사건 기록에 추가한다.
- 표본 수·통계 오차는 무작위 시뮬레이션 오차다. 근사 모델 자체의 오차까지 포함한 신뢰구간이 아니다.
- 근사 경로는 모든 발사체가 지정된 위치에 명중하는 시나리오다. 실제 게임의 추적·지형·반사 물리를 복원한 것으로 표시하지 않는다.

## 검증

`RangedApproximationChecks`는 충전/자탄 보존, 분할 피해 합계, 별도 폭발 사건, 근사 사용/해제/직접 입력 우선, 주요 무기 10초 교전, 증강·키트건 아케인, 특수 경계 조건을 확인한다. 기존 `RangedChecks`는 엄격 모드의 기존 수식·거부 조건을 유지한다.

`--approximation-ui-check`는 실제 WPF Automation 입력/Invoke/ExpandCollapse로 충전량 변경 → 계산 실행 → 근사 결과/상세 표시를 검증하고, 다크/라이트 ×100/125/150% 화면을 렌더링한다. 폭발·자탄·재장전 피해를 선택해도 전체 공격 계산 버튼이 원래 발사 동작으로 연결되는지 확인한다. 최소 창의 소수점 DPI 반올림으로 발생하던 불필요한 가로 스크롤을 수정했다. 물리적 다중 모니터 이동 또는 게임 클라이언트 실측을 대신하지 않는다.

최종 실행 결과는 `artifacts/ranged-completion-verification-2026-10-24.json`에 기록한다. 파생 공격은 독립 발사 모드가 아니며 본탄/재장전/기폭 사건으로 검사한다. 저장 피해가 0인 바일 디스차지를 임의로 충전된 공격으로 바꾸지 않는다.
