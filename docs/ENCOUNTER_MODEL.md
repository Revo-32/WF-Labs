# 교전 모델 v0.6.1

2026-10-11. 이 문서가 v0.6.0의 동적 CO·콤보 미지원 설명을 대체한다. 모든 근접 기믹이나 동적 TTK가 완성됐다는 뜻은 아니다.

## 공통 교전 조건

| 조건 | 시작 대상 | 결과 |
|---|---|---|
| 프라이머 적용 | 사용자가 선택한 상태·중첩 | 선택 동작 첫 타격의 직접 피해 |
| 아무 상태 없이 첫 타격 | 기존 상태 없음 | 첫 타격의 직접 피해 |
| 스탠스 한 사이클 | 기존 상태 없음 | 한 사이클 누적 직접 피해 / 실제 공속 적용 콤보 시간 |
| 5초 교전 | 기존 상태 없음 | 처음 5초 누적 직접 피해 / 5초 |
| 10초 교전 | 기존 상태 없음 | 처음 10초 누적 직접 피해 / 10초 |

에피타프·사이크론이라는 무기 이름만으로 원소 조합이나 상태 중첩을 확정하지 않는다. 프라이머 상태는 선택 칩과 중첩 입력으로 지정한다. 넉다운·띄우기는 동시에 CO 2종으로 계산하지 않고 마이크로웨이브는 별도 상태로 센다. 첫 타격에는 임의의 시간을 붙여 DPS라고 표시하지 않는다.

## 타격 처리와 출처

타격 전 대상 상태로 피해 계산 → 확률 상태와 강제 상태 부여 → 명중에 따른 콤보·방어력 변화 → 다음 타격 순서다. 같은 타격이 만든 상태는 그 타격의 CO에 소급하지 않는다. 피해 모드와 일반 근접 CO의 가산 브라켓, 무기별 CO 예외는 유지한다.

- 위키 스탠스 배열의 입력 순서·타수·배수·물리 배수·상태 확률 배수·강제 프록을 보존한다. `Knockback`은 충격, `Weakened`는 관통, `Bleed`는 베기 상태 이름과 연결한다. `Knockdown`은 충격과 다른 숨은 CO 상태다.
- 블라인드 저스티스 정지: 1타 강제 충격, 7타 강제 베기, 8타 넉다운. 타격별 CO 상대 배율은 1, 1, 0.5, 0.5, 0.5, 0.5, 0.5, 0.25다. 이를 모든 타격에 58%를 일괄 곱하는 처리로 대체하지 않는다.
- 타격별 CO 예외는 [위키 CO 문서](https://wiki.warframe.com/w/Condition_Overload_(Mechanic)?oldid=2815998#Stances)가 직접 인용한 [Melee Stances sheet v2](https://docs.google.com/spreadsheets/d/1FJ_RIEG2mlFGBQ__szeGoFM6azj23n0CqelBFO_MGGw/edit)를 사용한다. 현재 위키 배열과 입력 번호·타수·모션 배수·물리 배수가 일치하고, 동작이 분명한 146개 콤보를 연결했다. 불일치·공란·미해결 예외 101건은 자동 연결에서 제외했다. 146개라는 수가 시간 시뮬레이션 전체 지원 개수를 뜻하지 않는다.
- `data/stance-hit-co.json`에 타격별 규칙, `stance-hit-co-evidence.json`에 사용한 셀과 제외 사유, 출처·수집 시각·원본 XLSX SHA-256을 보존한다. `tools/import_stance_co_hits.py`는 입력 문서를 데이터로만 읽으며 수식을 실행하지 않는다.
- 상세 원문은 `melee-source-records.json`의 Condition Overload, Condition Overload (Mechanic), 각 피해 유형, Shattering Impact, Armor를 따른다. 넉다운·띄우기 보충 원문은 `encounter-posture-sources.json`에 보존한다.

## 시간과 상태

일반 공격의 반복 간격은 사용자 입력과 공속으로 정한다. 첫 명중은 0초다. 스탠스는 위키의 전체 콤보 시간을 사용하며 개별 타격 시각을 균등 분배하지 않는다. 각 타격을 해당 콤보 시작~종료 구간으로 보존한다. 한 사이클 전체 피해는 순서대로 계산할 수 있지만, 5초 경계에 걸친 일부 콤보나 상태 만료·화염 방깎 시점은 범위가 된다.

상태는 확률·피해 비중·타격별 강제 프록과 지속 시간으로 생성·만료된다. 오래 때렸다는 이유로 모든 가능한 상태를 영구 최대 중첩으로 가정하지 않는다. 일반 명중의 콤보 누적은 다음 타격의 블러드 러시·위핑 운즈에 반영한다. 넉다운·띄우기의 회복 시점이 확정되지 않은 구간은 보수적으로 CO 추가 0~1종의 범위를 둔다. 이는 유지율을 측정한 수치가 아니며, 해당 상태로 상태 확률·콤보 자체가 변하는 조건부 모드는 현재 거부한다.

화염 방깎은 즉시 50%가 아니라 시간에 따른 15/30/40/50% 단계를 적용한다. 상태 지속 시간과 종료 후 방어력 회복을 반영하며, 회복 중 재점화의 미검증 전개는 범위로 표시한다. 부식 중첩과 섀터링 임팩트도 같은 타격 상태 경로를 사용한다. 섀터링 임팩트는 충격 피해 명중에 적용하며 충격 상태 발동을 요구하지 않는다. 적의 레벨 보정 전 기본 방어력이 필요하고, 현재 방어력이 초기 상·하한에 걸린 경우에는 원래 레벨 배율 부재에 따른 범위를 표시한다.

128회 표본(경량 64회), 고정 시드 44061을 사용한다. 숫자는 기대값 추정이며 화면의 최소~최대는 시간·상태 불확실성의 범위다. 통계 신뢰구간이 아니다. 작업 하나만 백그라운드에서 실행하며 새 입력에 이전 작업을 취소한다.

## 결과의 경계

살아 있는 단일 대상에게 모든 타격이 명중한다는 조건의 직접 피해 모델이다. 적 체력 소진으로 누적 피해를 중단하거나 새 적으로 전환하지 않는다. 지속 피해 틱, 동적 TTK, 처치 연쇄, 다중 산탄의 순차 상태, 추가 타격, 일부 무기 고유 발동, 실드·오버가드 파괴 전이, 냉기·폭발·타우 등의 특수 전이는 아직 연결되지 않았다. 이런 빌드는 시간 결과를 계산 미지원으로 표시한다. 수동 선택한 아케인·외부 버프의 발동 상태는 고정이며 자동 유지율 계산이 아니다.

우측 상단 수식과 고정 상태 차트는 시작 상태의 별도 계산으로 명시한다. 교전 결과의 누적 피해·평균 DPS와 혼동하지 않는다. 타격별 CO 예외가 연결되지 않은 동작은 시간 계산을 거부하고, 기존 고정 상태 모델의 콤보 평균 근사도 그 사실을 표시한다. 무기 고유 방깎·강화 효과는 이후 이 교전 경로에 사건으로 추가해야 하며 CO만을 위한 별도 예열 수치를 만들지 않는다.

## UI와 검증

화면은 무기·모딩 : 상황 설정 : 계산 결과 = 1:1:2다. 최소 크기는 1760×820 논리 픽셀이며 Windows 배율에 따라 필요한 물리 화면 크기가 증가한다. 보관함·상황·결과는 독립적으로 스크롤한다. 드래그 카드는 1회 캡처한 실제 카드 이미지를 76% 불투명도로 커서에 따라 이동시키고 원본을 흐리게 표시한다.

Wanted Sans를 유지하면서 불투명 바탕, Display 글자 메트릭, Windows 설정을 따르는 Auto 안티앨리어싱, 픽셀 정렬을 적용했다. UI 기본 14 DIP, 카드 효과 13 DIP, 수식 Cambria Math를 사용한다. 폰트 교체나 실제 사용자 모니터의 완전 해결을 주장하지 않는다.

Release 빌드, 계산 회귀 204개, 위키 배열 전수 대조, 실제 버튼·저장 복원·스크롤·드래그 좌표 검사를 수행한다. 100/125/150% 및 최소·넓은 창의 렌더링을 직접 확인한다. PNG 생성 성공만으로 검수를 끝내지 않는다. 화면 밖 HWND 검사에서 PrintWindow가 검정 이미지를 반환하면 실제 화면 캡처 성공으로 기록하지 않는다. 게임 병행 부하와 사용자 모니터의 실제 글자 품질은 이 검사의 범위가 아니다.
