# WF Labs 다음 기능 계획

2026-10-24 기준. 이번 요청의 구현 범위는 기존 변경의 업데이트 배포와 후속 기능 정리이며, 아래 신규 기능은 아직 착수하지 않았다.

## 기준

모딩 → 수치 확인 → 빌드 비교의 정확도를 유지한다. 새 기능은 실제 게임 행동의 직전·직후에 연결하고, 최초 사용에 필요한 클릭과 입력을 줄인다. 확정값·시세·근사·인식 불확실성을 구분하며 상세 정보는 제거하지 않는다. 성능 최적화는 계산 동등성 검증 뒤 진행한다.

## 1. 성유물 보상 인식·시세 비교 — 다음 신규 기능

사용 흐름: 보상 화면에서 단축키 → 최대 4개 보상 후보 자동 인식 → 플래티넘·듀캇 비교 → 보상 선택. 인식된 이름을 품목 ID에 연결하고 오인식 후보는 클릭·방향키로 수정할 수 있도록 한다. 사용자의 게임 내 보상을 자동 선택하거나 거래를 실행하지 않는다.

첫 단계는 한국어 보상 스크린샷 입력과 품목 식별이다. 이후 요청 시 화면 캡처와 Warframe.market 조회를 연결한다. API 사양·이용 조건·호출 제한은 구현 착수 때 공식 문서로 다시 확인한다. 거래 플랫폼과 조회 대상 상태, 호가/거래 통계의 의미를 표시하고 실시간 호가를 판매 확정 가격처럼 표현하지 않는다.

완료 기준:
- 1~4개 후보, 한글 긴 이름, 서로 다른 해상도·UI 배율·화면 비율에서 평가 데이터셋과 품목 ID 정답률을 공개한다.
- 낮은 인식 신뢰도와 미인식을 표시하고 수동 수정 이후까지 같은 흐름으로 진행한다.
- 각 후보의 가격·듀캇·조회 시각·표본/주문 수를 한 화면에서 비교하며 가격 없는 항목은 0원으로 표시하지 않는다.
- 캐시·오프라인·요청 제한·서버 오류·취소를 처리한다. 화면 인식은 사용자 요청 시점에 제한한다.
- 전역 단축키 충돌, 게임 전체화면/테두리 없는 창, 팝업 초점과 게임 복귀를 검수한다.

## 2. 마스터리 제작·랭작 계획

사용 흐름: 숙련·보유 장비 표시 → 지금 제작할 수 있는 장비 보기 → 부족 재료·선행 장비 확인 → 제작/랭작 완료 처리.

처음에는 수동 체크와 저장으로 시작하고 계정 자동 수집은 별도 검증 후 판단한다. 장비·레시피·선행 장비·MR/평판/퀘스트/클랜 연구 조건을 연결한다. 시간 추정 하나로 순위를 단정하지 않고 '지금 제작 가능', '재료 적게 필요', '다음 해금에 필요'로 정렬한다.

완료 기준:
- 보유·숙련·제작 중을 별도 상태로 관리하고 재시작 후 보존한다.
- 제작 재료로 소모되는 장비는 먼저 숙련할 수 있도록 안내한다.
- 조우·키트건·40랭크 장비 등의 마스터리 예외를 출처와 함께 검증한다.
- 추천 이유, 부족 재료, 해금 조건과 다음 행동을 같은 화면에서 확인할 수 있다.

## 3. 모딩 화면 인식·빌드 가져오기

사용 흐름: 게임의 모딩 화면 캡처 → 무기·모드·랭크·리벤 인식 후보 확인 → 사용자가 적용 → 현재 계산과 비교. OCR 결과가 기존 빌드를 즉시 덮어쓰지 않도록 미리보기와 취소를 제공한다. 성유물 OCR에서 확보한 캡처·언어 대응·신뢰도 표시를 재사용한다.

완료 기준은 무기/슬롯/랭크/극성의 항목별 정답률, 부분 인식·중복·미지원 표시, 적용 전후 비교와 되돌리기다. 게임 메모리 접근을 선행 조건으로 삼지 않는다.

## 병행 유지보수

게임 패치별 공식 자료·위키 개정 대조와 계산 회귀, 실제 사용 중 재현된 문제 수정, 근사 모델의 확정 근거 보강을 각 배포에 포함한다. 물리적으로 서로 다른 DPI의 모니터 이동, 실제 IME 후보창, Windows 로그인/게임 실행 자동 시작 및 게임 병행 자원 사용은 자동 테스트와 구분해 검증 기록을 남긴다.

## 별도 후속 단계

익절티드·의사 익절티드와 워프레임 어빌리티 전체 시뮬레이션은 합의대로 뒤로 분리한다. 현재 로어·이클립스 같은 단순 외부 버프는 유지한다. 결과의 정확도와 세부 표현을 낮추는 최적화는 진행하지 않는다.
