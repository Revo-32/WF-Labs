- 익스포저 중첩 상한, 리탈리에이션 계단/상한, 도우티 Wiki 데스트레자 예제 +9.7배 및 +50배 상한.

- 동결 최종 치피 +1.0·캐린 배수·CO 최소 1종, 크레센도 초기 콤보.

스탠스 TTK는 개별 타격 시각을 생성하지 않는다. 처치 타격이 속한 콤보 시작~종료 범위를 반환하고 120초 이하의 완료 콤보만 실행한다. 미처치 표본을 분위수에서 제거하지 않는다. 동일 시드 재현성을 검사한다.

## UI·배포 검사

`--smoke <폴더>`는 실제 WPF 컨트롤에서 자료실 필터·탐색, 정지/전진 전환, 아케인 조건 변경·저장 복원, 모드 조작, 수용량·극성, 그래프 합계, 리벤 후보, 잘못된 입력을 검사한다. 다크/라이트/경량/작은 창과 새 자료실·아케인 화면을 PNG로 만들고 눈으로 확인한다.

Wanted Sans 글리프를 확인한다. 작은 글자는 Ideal/Grayscale, 창은 PerMonitorV2 매니페스트를 사용한다. 100%와 150% 카드 이미지를 생성한다. 실제 화면 밖 HWND에서는 본문 크기·이동/리사이즈/버튼 히트 테스트·DWM 모서리·비레이어드 창·DPI 인식 컨텍스트를 확인한다. SDK의 dotnet 호스트 대신 배포 EXE의 DPI 결과를 최종 기록으로 사용한다.

이 검사는 실제 사용자 모니터의 글자 품질이나 다중 모니터 이동, OS 마우스 드래그 전체 경로를 완전히 검증하지 않는다. 배포본의 `engine-check.json`, `ui-check.json`, `window-check.json`을 증거로 보존한다.

최종 배포 EXE 검사: UI smoke 종료 코드 0, PerMonitorV2=true, 96 DPI, Wanted Sans, 비레이어드 HWND 및 DWM 모서리 판정 통과. 진단 미리보기 폴더에 `import-replay-check.json`도 보존한다.

## 성능

Release 기본 계산 10,000회 평균과 2,048회 TTK의 반복 시간을 기록한다. 예시 빌드의 단일 프로세스 참고값이며 최대 부하나 실제 게임 병행 FPS·유휴 CPU·GPU·OCR 비용 측정이 아니다. 비표시 UI 렌더링 뒤 작업집합 역시 유휴 메모리 목표 충족의 증거로 사용하지 않는다.
