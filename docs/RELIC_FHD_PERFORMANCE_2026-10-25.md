## 실제 미표시 원인과 후속 수정

사용자의 실제 로그에서는 `2152.002 Script [Info]: ProjectionRewardChoice.lua: Got rewards`가 기록되었다. 기존 파서가 Lua 접두사를 허용하지 않아 진입 이벤트를 버렸다. `ProjectionsCountdown.lua: Relic timer closed`는 진입 직전과 종료 때 모두 나타나므로 종료 신호에서 제외하고, 보상 화면 자체의 `Selection countdown done`과 `Relic reward screen shut down`만 사용한다. 실제 로그의 관련 7줄을 계정 정보 없이 회귀 검사에 포함했다. 대기 프로세스 실행과 실전 감지 성공을 혼동한 이전 안내를 정정한다.

사용자가 직접 첨부한 `codex-clipboard-216ba978-b212-45c3-a778-55abc8bc7945.png`를 변경 없이 `artifacts/relic-user-2026-10-25/reward.png`로 복사했다. 3395×1410이며, 정답은 오르도스 프라임 설계도 / 포르마 설계도 / 스티아낙스 프라임 시스템 설계도 / 포르마 설계도이다. 기존 영역이 두 줄 이름의 첫 줄을 잘랐고 넓은 배경 탐색으로 넘어갔다. 상단 이름 행을 먼저 온전히 읽되 서로 다른 전처리 근거와 기존 확정 기준을 유지한다.

## 12시간 가격 저장

공유 Core `MarketPriceSnapshot`은 프라임 부품·세트 및 성유물 거래 품목을 대상으로 한다. 최초 전체 품목 manifest를 확보해 세트도 포함한다(검수 시 768개). OCR 후보 목록은 세트를 계속 제외한다. API는 품목별 주문을 읽고, 한 응답에서 게임 중/온라인 가격을 각각 계산한다. 요청 시작 간격 400ms, 오류 시 기존 데이터 보존·30초 간격의 제한적 재시도·3회 실패 후 중단 및 5분 뒤 재개를 적용한다. 30분마다 만료 여부를 점검하고 각 품목은 12시간이 지났을 때만 다시 요청한다. 따라서 정확히 매 정각 갱신하는 일정은 아니다.

보상 경로는 HTTP 요청 없이 저장 가격을 읽는다. 미준비 품목은 준비 중으로 표시하고 가격을 만들지 않는다. 12시간 초과는 갱신 지연으로 표시하며 가격 강조에서 제외한다. `현재 호가 확인`은 명시적으로 실시간 주문을 조회한다. 시장·플랫폼·크로스플레이·레퀴엠 충전/랭크 조건을 섞지 않는다. 첫 초기화와 재시작 시 지속성, 13시간 이전 가격 보존, 준비 중 요청 0회, 한 주문 응답의 두 필터, 세트 목록 분리, 최초 manifest 취득을 검사한다.

공식 근거: [품목별 주문 API](https://docs.warframe.market/docs/api/orders/), [캐시 권장과 초당 3회 제한](https://docs.warframe.market/docs/rules/overview/). 저장 시세는 조회 시점의 호가이며 거래 완료 가격이 아니다. 미래 마스터리 헬퍼의 세트/부품 구매 비용 비교에 재사용할 수 있지만 해당 헬퍼의 비용 최적화 기능 자체는 아직 구현 범위가 아니다.

최종 검수: 전체 계산·데이터 1,555개 통과(`relic-real-snapshot-core.json`), 최초 전체 manifest 확보 수정 후 성유물 집중 36개 통과(`relic-snapshot-focused.json`), 실제 Lua 형식 포함 자동 감지 검사 15개 통과(`relic-real-snapshot-auto-ui`), 기존 성유물 회귀 66개 기록 통과(`relic-real-snapshot-regression`), 전체 UI smoke 통과·153개 PNG(`relic-real-snapshot-smoke`). 실전 화면의 비교 결과와 150% 자동 설정 화면을 직접 확인했다. 모든 WPF 검사는 별도 Win32 데스크톱에서 사용자 데스크톱 전환·입력 없이 실행했다.

실제 가격 준비: 한국 시각 02:51:56에 768/768개 완료·실패 0개. 중단 후 재개 검사에서 기존 183개를 재사용하고 585개를 추가 갱신했다. 재개 구간 333.80초·HTTP 586회(전체 품목 manifest 1회 포함)이며 최초 전체 초기화 시간과 혼동하지 않는다. 결과는 `artifacts/market-snapshot-live-sync.json`, 가격은 사용자 LocalAppData의 `WF Labs/relic-market-cache`에 저장한다. 로컬 실행 파일을 갱신하고 최종 집중 검사 Core DLL과 SHA-256 동일함을 확인했다. 수정본 실전 진단은 `relic-auto-live-2026-10-25-02`에서 자동 감지 한 번을 최대 60분 기다린다. 새 실제 캡처가 발생하기 전에는 실전 성공으로 표시하지 않는다.

## 자동 감지 후속 구현 (2026-10-25)

- 기본 켜짐 `성유물 보상 자동 인식` 설정. 워프레임이 이미 전면이고 FHD 이상일 때만 자동 캡처한다. 창 활성화·게임 입력 전송·전체 화면 상시 OCR은 수행하지 않는다.
- 실시간 Windows 디버그 출력의 보상 진입/종료 메시지를 받는다. 채널에 다른 소비자가 있으면 점유를 빼앗지 않고 EE.log의 추가분만 500ms 간격으로 확인한다. 기록 회전·잘림·부분 줄·중복 메시지를 처리한다. 원본 로그 전체나 계정 데이터는 저장/전송하지 않는다.
- 공개 [WFInfo 이벤트 처리](https://github.com/WFCD/WFinfo/blob/master/WFInfo/Data.cs)의 `Pause countdown done`, `Got rewards`, `Relic timer closed` 메시지 식별자를 참고했다. 구현 코드는 자체 작성했다. 이 메시지들은 공식적으로 보장된 Warframe 외부 API 계약이 아니다.
- 보상 표시 애니메이션을 위해 신호 후 800ms 기다리고 포커스를 재확인한다. 오버레이는 종료 신호·게임 포커스 이탈·15초 수명에 따라 닫히며 자동 OCR 취소를 요청한다. 네이티브 Tesseract 실행 중인 한 패스의 즉시 중단까지 보장하지 않는다.
- 자동 인식은 단축키 없이 오버레이를 사용한다. 수동 캡처의 `게임 위에 표시` 설정과 구분한다. 자동 인식을 끄면 자동 감지·실행을 중지한다.
- 현재는 로그 기반 감지다. 로그가 지연되거나 이벤트 형식이 달라지는 경우를 화면으로 보완하는 경로는 아직 없다. 실제 FHD 보상 화면의 자동 감지→OCR→마켓→오버레이 전체 지연은 실전 검증 전이다.

검증: `artifacts/relic-auto-final-ui/checks.json`의 15개 검사 기록에 증분 로그, 비공개 Windows 이벤트 채널, 다른 프로세스 메시지 배제, 채널 충돌, 설정 이전, 실제 Automation Toggle과 100/125/150% 렌더 결과를 기록했다. 검수용 비공개 채널은 실제 DBWIN 채널에 연결하지 않는다. 전체 UI는 격리 Win32 데스크톱에서 실행하며 사용자 데스크톱으로 전환하지 않는다.

전체 계산·데이터 회귀 1,552개 통과(`relic-auto-core.json`), 성유물 회귀 66개 기록 통과(`relic-auto-regression/checks.json`, 실제 입력 검사는 명시적으로 생략), 전체 UI smoke 통과·153개 PNG(`relic-auto-smoke`). 최종 자동 설정 화면은 100/150% 이미지를 직접 확인했다. 격리 앱 전체의 로그 파일 감지 대기 3,011.6ms 동안 CPU 시간 15.625ms, 한 코어 기준 0.52%였다. 짧은 합성 대기 측정이며 실제 게임 플레이 중 부하나 실시간 로그 수신 부하·OCR 부하를 보장하지 않는다.

로컬 자체 포함 실행 파일 `artifacts/relic-app-0.10.0-preview.1/WFLabs.exe`를 갱신했고 검증한 Core DLL과 SHA-256이 일치한다. 공개 배포·설치 파일 생성은 하지 않았다. 자동 실전 진단 `relic-auto-live-2026-10-25-01`은 한국 시각 02:19:49에 실시간 로그 연결을 확인하고 15분 대기를 시작했다. 실제 결과는 캡처가 발생한 경우에만 같은 폴더의 result.json으로 확인하며, 대기 준비 성공을 인식 성공으로 세지 않는다.

## 앞선 성능 수치의 한계와 추가 발견

아래 표는 이전 최적화 단계의 합성 입력 측정값이다. 이후 복잡한 배경의 합성 FHD 4보상에서 100.8초 지연을 발견했고, 영역 분리·원본 크기 인식·이름 행 합의로 같은 입력을 약 8.2초까지 줄였다(`relic-fhd-textured-consensus`). 하지만 복잡한 배경의 1/2보상 합성 사례는 여전히 약 70초가 걸리며 불필요한 미확정 슬롯이 생겼다(`relic-fhd-textured-partial`). 따라서 일반 합성 입력의 2초대 수치를 모든 실전 입력의 성능으로 일반화할 수 없다. 자동 실행 연결만으로 이 OCR 문제를 해결했다고 보지 않는다.

## 최종 지원 조건

2026-10-25 사용자 최종 지시에 따라 **게임 실시간 캡처 최소 크기는 1920×1080(FHD)** 이다. QHD, 3440×1440, 4K도 검사한다. 앞서 요청한 1024×720은 비교 자료에만 남기며 실시간 지원 조건에서는 제외한다. 캡처 크기는 모니터 전체가 아닌 게임 클라이언트 영역의 물리 픽셀로 판단한다.

저해상도 기존 스크린샷과 이름 행만 잘라낸 이미지는 파일·영역 재인식 경로에서 계속 열 수 있다. 이를 FHD 실시간 성능 보장으로 해석하지 않는다.

## 구현

- 한국어 보상 이름 영역을 먼저 읽는다. 서로 다른 전처리 결과와 기존 품목 매칭·자동 확정 기준을 만족할 때만 빨리 종료한다. 화면 중앙 바깥 배치나 불명확한 글자는 기존 전체 화면·영역 정밀 인식으로 이어진다.
- 1~3개 보상은 전체 화면의 보상 제목 및 여러 패스의 일치가 필요하다. 다른 패스가 더 많은 보상을 찾았으면 작은 부분집합으로 조기 종료하지 않는다.
- 캡처 하나 안에서 같은 OCR 문자열의 품목 순위 계산을 재사용한다. 후보, 점수, 순서, 확정 결과가 캐시 없는 계산과 같은지 검사한다.
- 동일한 전처리 이미지의 PNG 인코딩을 언어별로 반복하지 않는다. 한국어 검사로 완료되면 혼합 언어 엔진은 로드하지 않는다.
- 후보를 검증하는 동안 읽기 전용 마켓 요청을 미리 시작한다. **보상 카드의 이름·가격은 검증이 완료된 결과에만 적용한다.** 일치하지 않는 선행 조회는 확정 결과로 표시하지 않는다.
- 마켓 요청 시작 간격 400ms를 지키면서 응답은 동시에 기다린다. 요청 대기·헤더·본문에 5초 기한을 적용한다. 90초 캐시, 중복 요청 합치기, 429 제한, 오래된 가격 표시, 취소를 유지한다. 네트워크 실패를 0 플래티넘으로 표시하지 않는다.
- 일반 이미지 읽기는 `인식·시세 N초`, 게임 단축키 경로는 캡처·전환 대기부터 포함한 `캡처·인식·시세 N초`를 표시한다.

## 측정 범위와 결과

UI 입력부터 OCR, 실제 API 응답, WPF 결과 반영까지 측정한다. 아래의 실측에는 **실제 게임 창을 전면으로 가져오고 캡처하는 시간은 포함되지 않는다.** 사용자의 다른 게임 플레이를 방해하지 않기 위해 마지막 검수는 별도 Win32 데스크톱에서 수행했다. 그 데스크톱으로 전환하지 않았으며 검사 프로세스 우선순위는 BelowNormal이다.

일반 4개 보상 합성 화면 + 실제 Warframe.market:

| 해상도 | 새 시세 조회 | 캐시 재사용 |
|---|---:|---:|
| 1920×1080 | 2.28초 | 0.90초 |
| 3840×2160 | 2.34초 | 0.90초 |

별도의 작은 글씨·어두운 금색 글씨 FHD 합성 화면에서는 각 3회씩 새 캐시 디렉터리로 실제 시세를 조회했다.

| 조건 | OCR 중앙값 | 시세 표시까지 중앙값 | 전체 시간 범위 | 자동 확정 |
|---|---:|---:|---:|---|
| 작은 한글 18px | 1.18초 | 2.37초 | 2.01–2.40초 | 매회 4/4, 오확정 0 |
| 어두운 금색 한글 22px | 5.64초 | 5.69초 | 5.64–6.27초 | 매회 4/4, 오확정 0 |

이것은 **합성 화면의 측정값**이며 모든 실제 보상 화면의 인식률·최대 지연을 보장하지 않는다. 1~4개 보상을 각 해상도에서 2회씩 읽은 32회 합성 회귀는 매회 기대한 품목을 자동 확정했다. 이 반복을 80개의 서로 다른 실제 보상을 검증한 것으로 세지 않는다. 이 회귀의 HTTP 응답은 fixture이며 실제 요청 간격·캐시 경로는 사용한다. 실제 API 측정과 구분한다.

FHD 전용 최적화 전의 동일 FHD 원본/비율 유지 1024×720 축소 비교에서는 작은 글씨가 FHD에서 4/4 자동 확정, 1024×720에서 1/4 자동 확정이었다. FHD 이상 기준을 정한 뒤에는 두 해상도에 적용되는 빠른 경로 자체가 달라지므로 이후 속도 차이를 해상도만의 효과로 해석하지 않는다. 낮은 해상도 원본을 확대해서 실제 FHD 원본인 것처럼 검수하지 않았다.

## 오버레이

성유물 탭의 `게임 위에 표시`를 켜면 게임을 전면에 둔 채 보상 이름, 판매 최저 플래티넘 호가, 듀캇, 시세 시각, 확인 필요·연결 실패·오래된 시세를 보여준다. 가격이 들어오는 순서대로 갱신한다.

- 별도 WPF/Win32 창, 게임에 DLL 주입·메모리 접근·게임 입력 전송 없음.
- 비활성·클릭 통과 창으로 게임의 보상 선택을 방해하지 않는다.
- 15초 후 또는 다른 앱으로 전환하면 닫힌다. 전역 단축키를 켠 경우 Ctrl+Shift+R을 다시 눌러 닫을 수 있다.
- 이름 교정은 WF Labs의 기존 검색창·방향키·Enter 흐름을 이용한다.
- 창 모드/테두리 없는 창이 대상이다. 독점 전체화면 및 HDR에서의 표시·캡처는 실제 검증하지 않았다.

사용자의 비방해 요청 전에는 검수용 실제 Windows 창에서 HWND 스타일, 전경 초점 보존, 네이티브 히트 테스트 통과, 닫힘, 다른 창 전환 시 자동 닫힘을 검사했다. 이후 검수에서는 별도 데스크톱의 렌더링·배치만 검사하며 실제 입력·전경 전환 검사는 제외한다. 이것을 실제 워프레임 보상 선택 중 검증한 것으로 표현하지 않는다.

Windows 동작 근거: [Microsoft Window Features](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features).

## 재현 산출물

- FHD 이상 해상도·인식·시간·실제 API: `artifacts/relic-fhd-isolated-performance/checks.json`, `timings.json`

- 기존 실제 한국어 장면 4개·16칸 및 비보상 입력 3개: `artifacts/relic-fhd-isolated-real/checks.json`
- 기존 버튼·취소·오프라인·배치 회귀: `artifacts/relic-fhd-isolated-ui/checks.json`
- 오버레이의 격리 렌더링: `artifacts/relic-isolated-overlay/`
- 비방해 요청 전 검수용 HWND 검사: `artifacts/relic-performance-final/checks.json`
- 각 격리 실행의 `isolation.json`: 데스크톱 미전환, 실제 입력 검사 제외, 종료 코드 기록

격리 검사 도구는 `tools/run-isolated-ui-check.ps1`이다. `SwitchDesktop`을 호출하지 않으며, `WF_LABS_NONINTERACTIVE=1`로 실제 마우스·게임 캡처 검사를 제외한다. 품목·가격·교정 검사는 저장 화면과 내부 WPF 이벤트로 실행한다.

## 한계

실제 한국어 FHD 보상 선택 장면에서 단축키 → 캡처 → 오버레이 → 게임 내 선택까지의 종단 검수는 남아 있다. 확보한 실제 공개 보상 장면은 FHD 미만이므로 정확도 회귀용으로만 사용했다. 모호한 화면의 정밀 재검사는 더 오래 걸릴 수 있고, 마켓 장애 중 새 가격을 보장할 수 없다. 새 가격이 없는 항목은 오류·미확정으로 남겨 확정 가격과 구분한다.

로컬 개발본에 반영하며 공개 업데이트·설치 파일 배포는 이번 작업에서 실행하지 않는다.
