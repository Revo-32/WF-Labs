# 한국어 성유물 실제 화면 검수와 자동 확정 개선

2026-10-24~25 · 로컬 `0.10.0-preview.1`. 공개 배포·설치 파일·업데이트 feed는 변경하지 않았다.

## 사용자 요청과 범위

실제 한국어 보상 스크린샷을 먼저 검수하고, 일반적으로 이름을 직접 고르지 않아도 시세가 나오게 개선했다. 영어 게임 화면의 인식 품질은 이번 지원·검수 범위가 아니다. 한국어 전용 모델과 한·영 보조 모델을 내부적으로 비교하지만 결과는 한국어 품목 사전의 고유 ID에 연결한다.

워프레임이 실행 중이지 않아 사용자가 실제 스크린샷부터 확인하도록 지정했다. 이번 결과는 공개된 실제 게임 이미지·영상 프레임과 앱의 파일 불러오기 흐름에 대한 결과이며, 실행 중인 게임의 캡처·게임 복귀를 완료했다고 표현하지 않는다.

## 실제 입력과 출처

| 입력 | 원본 특성 | 보상 |
|---|---|---|

| `reward-full-dark.png` | 원본 영상 자체가 640×360, 2.0초 프레임 | 세바고스 뉴로옵틱스, 라보스 뉴로옵틱스, 바자 리시버, 벨록스 배럴 |

- 금색 화면: [제작자 게임 가이드](https://joynplay.kr/워프레임-프라임-캐릭터-프라임-무기-파밍-얻는-방법/). WebP 원본을 PNG로 무손실 변환했다. 같은 글의 보이드 잔영 툴팁을 비보상 음성 사례로도 사용했다.
- 붉은 화면: [공개 제작자 게시물](https://gall.dcinside.com/mgallery/board/view?id=ordis&no=437481). 원본 850×331에서 다른 프로그램의 OCR·가격 오버레이가 있는 하단을 제외하고 실제 게임 부분 `(0,0)-(850,217)`만 사용했다. 타 프로그램의 코드나 출력값을 인식 정답으로 사용하지 않았다.
- 두 영상: [공개 한국어 플레이 영상 게시물](https://gall.dcinside.com/mgallery/board/view?id=ordis&no=429163), 영상 ID `5861535`, `5862553`. 다른 앱의 OCR 오버레이가 표시되기 전 프레임을 추출했다. 각 영상의 0초 전투 장면도 비보상 입력으로 사용했다.

독립된 보상 장면은 4개, 보상 칸은 16개다. 같은 화면의 전처리·배율별 반복 검사나 여러 언어 모델 실행을 새로운 표본으로 합산하지 않는다. 밝은 영상의 `2 X 포르마`는 품목 ID·거래 불가 여부를 검증했으며, 이번 표의 16개는 수량 합계가 아닌 보상 칸 수다. 가격 표시는 개당 호가 기준이다.

출처·원본/입력 SHA-256·프레임 시각·자르기 범위·한국어 원본을 보고 정한 정답 ID는 `tests/fixtures/relic-real-manifest.json`에 기록했다. 타인의 이미지·영상은 무시되는 로컬 `artifacts/relic-real-2026-10-24/`에만 두며 앱이나 Git 배포에 넣지 않는다.

## 확인한 문제와 수정

초기의 원본/밝은 글자 두 경로는 금색·붉은 실제 이미지 8개 보상에서 올바른 최상위 후보를 찾지 못했다. 합성 한국어 화면 통과만으로 실제 화면에서 잘 동작한다고 판단할 수 없었다.

수정 사항:

- 흰색뿐 아니라 어두운 금색·붉은 글자를 위한 색상·국소 대비·반전 전처리를 추가했다. [Tesseract 공식 품질 안내](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)의 작은 영역 분리·글자 배율·여백 원칙을 적용했다.
- 보상 글자 행 → 겹치는 작은 영역 → 실제 후보 중심을 이용한 카드별 영역 → 필요 시 한 줄씩 다시 읽는 순서로 정밀 인식한다. 첫 읽기에서 네 이름이 두 결과에 정확히 일치하면 불필요한 추가 처리를 생략한다.
- 한글 사이의 짧은 영문 잡음과 단독 자모를 정리한다. 긴 미인식 영문 조각은 남겨 부품 이름이 통째로 빠진 결과를 일반 설계도로 잘못 확정하지 않게 했다.
- 같은 위치의 여러 OCR 결과는 합치고, 서로 다른 칸의 같은 보상은 별도로 유지한다. HUD 아이콘의 `Vo`, `iS`를 레퀴엠 모드로 처리하지 않는다.
- 검색창의 부분 일치 검색과 OCR의 전체 이름 비교를 분리했다. 공통 `뉴로옵틱스 설계도`만으로 특정 프레임을 자동 확정하지 않는다.
- 정확한 이름뿐 아니라 가까운 후보와 충분히 구분되는 한글 이름, 여러 문자 처리 계열이 지지하는 이름도 자동 확정한다. 같은 전처리에서 겹치는 창을 반복한 것을 독립적인 동의로 중복 계산하지 않는다. 강한 경쟁 후보가 서로 충돌하면 확인을 남긴다.
- `프라임`이 빠졌더라도 고유 이름이 정확하고 구체적인 부품명이 충분히 읽힌 경우는 복구한다. 고유 이름과 `설계도`만 있거나 부품 영역이 통째로 읽히지 않으면 이 규칙을 쓰지 않는다.
- 자동 확정한 칸은 즉시 시세를 조회하고 **자동 인식 완료**로 표시한다. 수동 확인은 불확실한 칸에만 남긴다. 비교 뒤에도 이름 수정은 가능하다.

유사도와 OCR confidence는 정답 확률이 아니다. 문턱값을 낮춰 모든 후보를 무조건 확정하는 방식은 사용하지 않았다.

초기 실제 화면 개선 직후에는 자동 확정이 5/16이었고, 사용자의 추가 요청 후 15/16으로 늘었다. 남은 한 칸은 어두운 압축 영상의 **세바고스 프라임 뉴로옵틱스 설계도**다. 이 입력은 이름 자체가 충분히 남아 있지 않아 수동 교정으로 처리했다. 위 결과는 이 4개 장면에 대한 결과이며 모든 테마·UI 배율·HDR·동영상 압축에서 같은 비율을 보장하지 않는다.

전투 장면 2개와 보이드 잔영 툴팁 1개에서는 보상·확정 가격을 생성하지 않았다.

## 검수 방법과 산출물

`--relic-workflow-check <manifest> <output>`는 실제 WPF **이미지 불러오기** 버튼을 호출하고 파일 선택 경로만 주입한다. 실제 이미지 디코더·OCR·품목 확정·실제 공개 마켓 API를 사용한다. 이후 실제 후보 버튼·입력·방향키·Enter 이벤트로 수정 기능도 확인한다. 수정 검사를 위해 이미 자동 확정된 칸도 다시 선택했으며, 이를 사용자가 반드시 해야 하는 작업 수로 세지 않는다. 보고서의 `needed`가 최초에 정말 수동 선택이 필요했는지를 나타낸다.

검사 항목은 자동 확정 후 클릭 없이 호가 조회, 품목 ID·듀캇·거래 불가 일치, 중복 보상 칸, 불확실한 후보의 가격 억제, 정정 후 새 품목의 호가, 100/125/150% 배율의 카드 배치다. 실제 마켓 응답은 검수 시각의 호가이며 이미지나 게임 계정은 전송하지 않는다. 거래 게시·메시지 발송도 하지 않는다.

전체 계산·성유물 검사 **1,547개**, 실제 화면 사용 흐름 **125개**, 기존 성유물 UI 회귀 **65개**를 통과했다. 자동 확정과 교정 결과는 중복 검사 수를 합산한 인식률이 아니다. 미확정 제목 표시를 마지막으로 다듬은 뒤 해당 실제 화면의 **28개** 흐름도 다시 통과했다.

전체 UI smoke도 정상 종료했다. 마지막 비보상 한글 잡음 필터 보강 뒤 실제 이미지 7개 사용 흐름을 재실행해 125개를 통과했다. 공개 실행 파일과 검사 대상 계산 엔진 DLL의 SHA-256이 같으며, 입력 이미지 7개의 해시도 기록과 일치한다. 종합 결과는 `artifacts/relic-korean-validation-summary.json`이다.

최종 검수 결과는 아래 산출물을 참조한다.

- 실제 화면·자동 시세·교정·배치: `artifacts/relic-korean-verified/checks.json`
- 최종 실행 파일의 기존 65개 OCR/UI/오프라인/단축키/취소/영역 선택 회귀: `artifacts/relic-korean-regression/checks.json`
- 전체 계산·성유물 검사: `artifacts/relic-final-all-core.json`
- 최종 실행 파일의 미확정 보상 제목·교정: `artifacts/relic-korean-uncertain-final/checks.json`
- 기존 전체 화면 smoke: `artifacts/relic-korean-published-smoke/ui-check.json`
- Release self-contained 빌드: `artifacts/relic-korean-final-publish.log`

검수 명령:

```powershell
& E:\CODEX\Tools\dotnet8\dotnet.exe run --project tests/TennoForge.Checks -c Release -- --relic-only artifacts/relic-core.json
Start-Process -FilePath .\artifacts\relic-app-0.10.0-preview.1\WFLabs.exe -ArgumentList @('--relic-workflow-check','artifacts/relic-real-2026-10-24/fixtures.json','artifacts/relic-korean-final') -WindowStyle Hidden -Wait
```

파일 선택은 진단 코드로 주입한다. 시스템 클립보드를 덮어쓰지 않는다. 화면 원본·전처리 중간 파일은 `--relic-image-check <image> <output>`에서만 명시적으로 저장한다. 일반 앱 사용 중에는 원본과 OCR 원문을 자동 저장하지 않는다.

후속 성능·지원 해상도·오버레이 변경은 [FHD 최적화 검수](RELIC_FHD_PERFORMANCE_2026-10-25.md)를 참조한다. 아래 시간 관련 제한은 저해상도 실제 표본에 대한 기록으로 유지한다.

## 남은 실제 환경 확인

- 사용자가 미룬 실행 중 게임의 보상 화면 캡처 → 비교 → 실제 게임 복귀, 독점 전체화면/HDR, 물리 모니터 이동은 별도 검수다.
- 저해상도·압축 입력의 정밀 재인식은 수십 초 걸릴 수 있다. 이번 작업은 인식 정확도와 자동 확정에 우선순위를 두었으며, 실전 보상 선택 제한 시간 안에 끝난다고 검증한 것은 아니다. 일반 해상도 게임 캡처의 실제 소요 시간도 이후 측정해야 한다.
- 새 Windows 환경의 VC++ 런타임 설치, API 사용 앱 공개 전 운영진 연락 조건은 기존 배포 전 항목으로 유지한다.

로컬 실행 파일은 `artifacts/relic-app-0.10.0-preview.1/WFLabs.exe`다. 이번 검수로 공개 업데이트를 배포하지 않았다.
