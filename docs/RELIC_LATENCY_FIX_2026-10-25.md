# 성유물 실전 지연 수정과 무기 선택 UX 검수

## 재현한 원인

사용자의 3440×1440 실전 캡처에서 보상 감지·캡처는 약 0.885초였다. OCR의 단어 묶음은 화면 너비의 고정 비율로 간격을 비교했으므로 울트라와이드에서 아쏘다이 설계도와 브롱코 리시버를 한 이름으로 합쳤다. 네 보상이 모두 확정될 때까지 결과를 표시하지 않았고, 전체 장면 재검사로 진입했다. 해당 원본의 기존 정밀 인식 재현 시간은 53.769초였다. 실제 게임에서는 선택 종료 시 취소되어 결과를 표시하지 못했다.

## 변경

- 화면 가로세로 비율을 반영해 글자 높이에 비례한 단어 간격으로 카드 이름을 분리한다.
- 발견한 미확정 이름의 경계를 먼저 재검사한다. 보상명이 없는 위쪽 영역의 중복 검사를 실시간 경로에서 생략한다.
- 자동·오버레이 캡처에서는 전체 장면 정밀 재검사로 넘어가지 않는다. 6초가 지나면 추가 OCR 읽기를 시작하지 않는다. 진행 중인 네이티브 읽기는 완료하므로 엄격한 6초 제한은 아니다.
- 서로 다른 전처리 결과가 뒷받침한 보상부터 저장 시세와 함께 표시한다. 확정 기준을 낮추지 않는다. 미확정 항목은 수정 가능하게 남긴다.
- 12시간 시세 스냅샷을 재사용한다. 인식 중에는 시세 HTTP 요청을 하지 않는다. 수동 파일 정밀 인식 경로는 유지한다.
- 무기 선택창의 테두리·이름·화살표 어디를 클릭해도 검색 목록이 열린다. 검색·방향키 이동은 현재 무기를 바꾸지 않으며 후보 클릭 또는 Enter로 확정한다.
- 지원 무기명 옆에 공통 인카논 버튼을 배치한다. 근접 변신·진화와 주/보조무기의 시작 형태·진화·완충 자동 전환을 직접 편집한다. 미지원 무기에 인카논을 임의 추가하지 않는다.
- 인카논 팝업은 제목과 완료 버튼을 고정하고 설정 내용만 스크롤한다.

## 최종 실행 파일의 저장 화면 재생

`artifacts/relic-live-latency/verified/fixtures.json`의 최종 측정이다. 캡처와 게임의 보상 등장 애니메이션 대기 시간은 포함하지 않는다. 첫 가격은 일부 보상이 먼저 표시된 시점이며, 전체 완료 시간과 구분한다.

복잡한 배경에 이름을 합성한 FHD 시험 화면은 진단 PNG 기록을 포함해 6.017초에 4/4를 확정했다. 실제 게임 표본으로 간주하지 않는다. 실행 중 부하에 따라 시간은 달라진다.

## 검사 결과와 범위

- 전체 엔진 검사: 1,555개 통과, 실패 0 (`core.json`).
- 실제 보상 원본 3개 사용 흐름: 94개 통과 (`verified/checks.json`). 자동 확정·좌우 순서·저장 가격·키보드 교정·125/150% 배율 포함.
- 기존 OCR·교정·취소·오프라인 UI 회귀: 66개 통과 (`regression/checks.json`).
- 무기 검색·인카논 선택: 43개 통과 (`weapon-published/checks.json`). 근접 세라믹 대거, 주무기 브래튼 프라임, 보조무기 라토 프라임의 실제 버튼, 변신/진화 적용, 계산 입력, 저장 복원 포함.
- 전체 WPF smoke 정상 종료, PNG 153개 생성 (`smoke/ui-check.json`). 인카논 표시가 추가된 전체 화면과 최종 팝업 PNG도 직접 확인했다.
- 격리 오버레이 992/1440px 배치 검사 통과 (`overlay/checks.json`).
- 검사는 전환하지 않는 별도 Windows 데스크톱 또는 창 없는 진단에서 수행했다. 게임 키 입력은 보내지 않았다.

실전 감지 → 신규 프레임 캡처 → 오버레이 표시까지의 수정 후 전체 시간은 새 실제 보상 라운드에서 아직 측정하지 않았다. 저장된 실전 원본의 재생 결과를 그 측정으로 대체하지 않는다. 새 OCR 읽기를 시작하지 않는 예산은 인식률 보장이 아니다. 판독하기 어려운 항목은 확인 필요로 남을 수 있다.

## 로컬 실행

수정본: `artifacts/relic-latency-fix-app/WFLabs.exe`.

기존 설치본 0.9.0과 공개 업데이트 배포는 변경하지 않았다. 작업 파일을 로컬 산출물 폴더에 백업했다. 수정본을 `--background`로 실행할 때 최소화 상태와 전경 창 유지 여부를 확인했다 (`background-launch.json`). 이후 사용자가 앱을 종료했다고 알렸으므로 재실행하지 않는다.
