# OCR 품질·자원 사용·첫 사용 흐름 검수 · 2026-10-27

대상은 공개 전 로컬 후보 `1.0.0-rc.3`이다. 게임이나 다른 앱의 포커스를 옮기지 않고, 저장 자료와 전환하지 않는 별도 Win32 desktop에서 검수했다. 기존 RC1·RC2 사본과 복구 저장소의 HEAD·index는 유지한다. 공개 GitHub 릴리즈는 수행하지 않는다.

## 기준과 측정 방법

- 정확한 품목·옵션·수치·부호·좌우 순서와 기존 자동 확정 기준을 우선한다. 불확실한 값을 추정하거나 confidence 임계값을 낮춰 시간을 줄이지 않는다.
- 첫 사용자가 자동 인식의 상태와 다음 행동을 알아볼 수 있도록 표준 메뉴, 검색, 확인·취소, 펼침과 상태 표시 문법을 사용한다. 구현 성공만으로 초보자의 사용성을 검증했다고 표현하지 않는다.
- 비교 기준은 작업 전 RC2 소스 사본이다. 측정 dispatch와 `ResourceChecks.cs`만 추가한 상태로 빌드했다. 원래 소스·모델 해시는 `artifacts/ocr-performance-20261027/baseline.json`에 보존했다.
- 같은 PC·16개 논리 프로세서·BelowNormal·200ms 샘플링으로 자체 프로세스 CPU 시간, 시스템 전체로 정규화한 CPU%, working set, private bytes, managed bytes, 할당량과 GC 횟수를 수집한다. 실제 화면을 캡처하거나 다른 프로세스를 순회하지 않는다.
- 대기 8초 후 숨김 일정·표시 일정·성유물 첫 입력/반복·리벤 단일/두 카드·OCR 후 대기를 구분한다. 별도의 검수나 빌드가 끝난 뒤 비교를 순차 수행하며, 강제 GC나 working set 비우기는 사용하지 않는다.
- 저장 이미지의 OCR 시간에는 실제 게임 감지 대기, 캡처, 온라인 시세 요청, 오버레이 표시와 GPU/FPS 영향이 포함되지 않는다. 작은 표본의 중앙값을 실전 전체의 상한으로 해석하지 않는다.

## 반영한 변경

1. **Gray8 직접 변환.** PNG 직렬화·다시 읽기 대신 Leptonica의 word stride와 endian 규칙으로 Pix를 준비한다. 색상 이미지·소수 DPI는 기존 PNG 경로를 유지한다. `OcrPixels.cs`의 전용 pool은 크기·개수를 제한하고, 반환되지 않는 큰 배열까지 명시적으로 지운다. 성유물의 언어별 reader는 같은 Pix를 순차 사용한다.
2. **반복 준비·문자 매칭 축소.** 리벤 MR normal/dim 탐지에 축소 BGRA 준비를 공유하고 ONNX 결과 버퍼를 수명 내에서 직접 읽는다. 성유물 매칭은 동일한 점수식을 유지하면서 카탈로그 인덱스·한글 분해·DP 임시 행을 재사용한다. 카탈로그 변경과 복제는 캐시를 무효화한다.
3. **세 보상 경로.** 초기 compact 결과가 불확실한 2~3개 보상일 때 원본 이름 행을 먼저 읽는다. 기존 네 보상의 빠른 경로는 유지한다. 640×360 보관 이미지는 후기 fallback에서 작은 bbox를 원본/반전 배율과 TextLine로 재판독하며, FHD 실시간 조건과 구분한다.
4. **기존 모델의 정수형 변환.** Tesseract 5.5.3의 공식 `--convert_to_int`로 기존 wfkor/eng를 변환했다. 추가 학습이나 게임 파일·폰트 추출은 하지 않았다. `SOURCES.json`의 upstream 원본 해시는 그대로 두고 `runtime-models.json`, `wfkor.model.json`, `MODEL-MODIFICATIONS.txt`에 변환 방법·원본/결과 해시·평가 한계를 남겼다.
5. **상시 작업 감소.** 전경 HWND/PID identity를 재사용하고 숨긴 일정 대시보드의 재구성을 생략한다. 알림·만료·실제 표시 중인 오버레이는 계속 처리한다. 인벤토리 자동 검색은 250ms 협력식/128MiB/1MiB 청크로 나눠 이어 읽으며 OCR이 시작되면 청크 사이에서 양보한다. 실제 인벤토리 내용은 검수용 가짜 자기 프로세스 영역과 구분한다.

직접 Pix 변환은 [Tesseract .NET Pix 소스](https://github.com/charlesw/tesseract/blob/5.2.0/src/Tesseract/Pix.cs)와 [PixData 소스](https://github.com/charlesw/tesseract/blob/5.2.0/src/Tesseract/PixData.cs)의 word stride/endian 규칙을 따른다. 이름 행의 범위·배율·PSM 선택은 [Tesseract 품질 지침](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)을 참고했다. 정수형 변환에는 정확도 손실 가능성이 있으므로 [공식 학습·변환 문서](https://tesseract-ocr.github.io/tessdoc/tess5/TrainingTesseract-5.html)의 설명만으로 채택하지 않고 아래 실측을 통과시켰다.

- **48개 회귀 시나리오:** 통과 48, 전체 기대 결과 일치 47, 잘못된 자동 확정 0. 입력에는 실제 카드·계정 정보를 가린 실제 글자·재구성 장면·합성 자료·비대상 화면이 섞여 있다. 자료 목록과 결과는 `artifacts/ocr-performance-20261027/ocr-manifest.json`, `final-ocr-48/results.json`이다.
- 완전 일치가 아닌 1개는 이전부터 최소 3개 확정을 통과 조건으로 두었던 어두운 **640×360 보관 화면**이다. 4개 중 3개를 확정하며 오확정은 없다. 이 조건을 변경하거나 성공으로 과장하지 않았고, 실시간 지원 기준은 FHD 이상이다. 다른 밝은 640×360 사례의 셰이드 시스템 누락은 이번에 4개 모두 복구했다. 작은 보관 이미지는 수십 초의 후기 재시도가 남아 있어 실시간 속도로 권장하지 않는다.
- **보류 전사 162줄:** float/int의 raw 문자열이 공백까지 동일하고 수치·부호·단위 변경이 없다. validation은 765자 중 4문자 오류(CER 0.523%), test는 824자 중 4문자 오류(CER 0.485%)로 기존 오류도 그대로다. 실제 게임 전사는 12줄이고 나머지는 합성 자료이므로 한국어 전반의 정확도 보장은 아니다.
- 변환 평가 원본은 `E:/CODEX/Workspaces/WFLabsOcrQuantization-20261027/evaluation`에 있다. 기존의 아이콘 `#`·추가 `%` 및 합성 이름 문자 오류 8건도 `existing-errors.json`에 보존했다. OCR 이후의 사전 매칭/옵션 파싱 성공과 raw 문자 무오류를 혼동하지 않는다.
- 픽셀/DPI·텍스트/신뢰도·모델 해시와 MR 준비 비교, 카탈로그 매칭 동등성, 전체 계산·UI 결과는 아래 통합 검수 기록을 따른다. 실제 게임 메모리 동기화 성공이나 물리 키보드 입력을 검수했다고 확대하지 않는다.

## UX 변경과 검토 방식

자동 인식 상태·스위치·설정을 성유물과 리벤에서 같은 위치와 용어로 제공한다. 수동 이미지 입력과 가격 필터는 표준 ContextMenu로 묶고 보상은 이름·가격부터 보여준다. 이름 수정은 명시적으로 시작하며 선택·취소 후 읽기 화면으로 돌아온다. 출처·프라이버시·가격 주의·최소 해상도는 삭제하지 않고 펼침 영역에 보존한다. 장비는 동기화 전에는 동기화가, 자료가 있으면 실제 미보유 장비의 목표 등록이 우선이다. 비어 있는 리벤의 적용·장착 리벤 불러오기는 실제 유효성에 맞춰 비활성화한다.

독립 검토자가 일정·장비·성유물·리벤·모딩의 실제 렌더 자료를 확인했다. 창뿐 아니라 열린 메뉴·후보 popup도 별도 렌더한다. 실제 UIA 명령·확인/취소·상태 복원과 화면 잘림 검수를 수행하되, 비활성 격리 HWND의 물리 keyboard focus/mouse capture 제약은 검사 결과의 `menuLimitations`에 기록한다. 이는 신규 사용자 관찰 실험을 대신하지 않는다. 상용 UI 근거와 확인 화면은 `docs/UX_REVIEW_2026-10-27.md`를 따른다.

## 최종 자원 측정·통합 산출물

다른 검수·빌드가 끝난 뒤 `baseline-1 → candidate-1 → candidate-2 → baseline-2` 순서로 완료했다. 첫 입력은 새 프로세스 안의 첫 해당 입력이며 OS 디스크 캐시를 비우지 않았다. 성유물은 3440×1440 재구성 장면(사용자가 제공한 실제 글자), 리벤은 저장된 실제 단일/전후 카드 자료를 사용했다. 성유물 첫 입력과 각 리벤 단계는 각각 2개 관측, 성유물 반복은 4개 관측의 중앙값이다.

| 저장 이미지 인식 단계 | RC2 소스 | RC3 | 시간 감소 | CPU 시간 RC2 → RC3 |
| --- | ---: | ---: | ---: | ---: |
| 성유물 3개 첫 입력 | 2.918초 | 1.020초 | 65.0% | 3.438 → 1.125초 |
| 성유물 3개 반복 | 2.299초 | 0.896초 | 61.0% | 2.359 → 1.117초 |
| 리벤 단일 첫 입력 | 2.463초 | 1.421초 | 42.3% | 2.797 → 1.563초 |
| 리벤 두 카드 첫 비교 | 2.568초 | 1.994초 | 22.3% | 4.305 → 3.234초 |
| 리벤 두 카드 반복 | 2.060초 | 1.442초 | 30.0% | 3.492 → 2.656초 |

성유물 반복 한 번의 managed 할당은 중앙값 **189.9 → 37.4MiB(80.3% 감소)**, 리벤 두 카드 반복은 **235.8 → 214.4MiB(9.1% 감소)**였다. 이 값은 작업 동안 할당한 누적 바이트이며 작업 후 RAM과 다르다. 모든 OCR 뒤 10초 대기의 마지막 working set 중앙값은 **666.2 → 653.9MiB**, private bytes는 **583.1 → 571.0MiB**였다. 리벤 첫 입력 단계의 working set은 460.8 → 480.0MiB, 두 카드 첫 비교는 632.8 → 644.8MiB로 증가한 관측도 있다. 이번 RAM 절감은 소폭이며, 큰 개선은 성유물의 임시 할당과 OCR CPU 시간에서 나왔다.

숨긴 일정과 모딩 대기의 CPU는 전체 시스템 기준 중앙값 약 **0.132% → 0.142%**, 일정 표시 중은 **0.571% → 0.556%**였다. OCR 후 대기는 0.073% → 0.107%로, 작은 절대 CPU 시간의 변동이 있어 대기 CPU가 유의하게 개선됐다고 주장하지 않는다. 작은 2회 측정으로 장기 누수·실전 FPS 영향을 단정하지 않는다. wfkor+eng 파일 합계 **27.2 → 7.5MiB(72.6% 감소)**도 RAM 절감과 별개로 기록한다.

원자료는 `artifacts/ocr-performance-20261027/resource-final-{baseline,candidate}-{1,2}`의 `samples.json/csv`, `phases.json`, `checks.json`, `process-samples.json/csv`와 `resource-comparison.json`이다. 4회 모두 같은 성유물 3개와 리벤 단일/두 카드의 정확한 옵션·수치·부호·교차 확인을 통과했다. `compare-resources.py`로 원자료의 중앙값과 범위를 다시 계산할 수 있다.

통합 검수는 `validation-complete/validation-summary.json`의 **18단계 통과**, 계산·데이터 **1,769개 통과/실패 0**을 확인했다. 단계별 원래 실행 폴더와 첫 실패 보존 경로는 `validation-complete/provenance.json`에 있다. 중간 검수의 native 표시 시점, 메뉴의 비활성 HWND 제약, popup 컨테이너 생성과 UIA callback 대기 문제를 수정하고 관련 단계를 다시 실행했다. 마지막에는 실제 수동 교정 뒤 페이지 상태가 낡아 있는 제품 문제도 고쳐 성유물 **95개 검사**를 통과했다. 실패한 첫 실행을 지우거나 전 단계를 하나의 연속 성공 실행으로 표현하지 않는다.

최종 자체 포함 실행본의 검사와 압축 해제된 검수 사본은 `native-final` 및 `E:/CODEX/Workspaces/WF-Labs-Test-RC3/검수 결과.json`을 따른다. 실제 게임 캡처부터 표시까지의 체감 시간, 장시간 플레이의 FPS, 새 PC, 물리 모니터 이동 및 신규 사용자 관찰 실험은 이번 결과에 포함되지 않는다.
