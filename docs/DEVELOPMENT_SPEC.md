## 2. 정확도 계약

각 결과는 계산 규칙 버전, 데이터 버전, 입력 빌드, 대상 조건, 가정, 미지원 항목, 출처, 계산 중간값을 가진다. **스탠스는 WF Wiki가 맞다는 가정으로 개발한다.** 사용자에게 게임을 켜서 재검증하거나 영상을 수집하도록 요구하지 않는다. 위키 일치 검증을 지원 기능의 수용 기준으로 삼는다.

| 검증 단계 | 의미 | 현재 상태 |
|---|---|---|
| 출처 고정 | 위키 URL·개정 번호·원문 해시·인용 범위 보존 | 모듈 전체: 무기 911 / 스탠스 표 134 / 아케인 166 / 모드 1,550 |
| 원문 일치 | 타격 배율·횟수·동작 시간·강제 상태이상 등 변환 결과 대조 | 228개 기본 무기·1,248개 동작 원문 전수 대조 |
| 계산 일치 | 위키 규칙으로 작성한 독립 기대값·경계값과 결과 대조 | 141개 검사 통과; 실제 호환 조합 1,990건 계산 / 5,902건 명시적 거부 |
| 지원 범위 | 계산되는 효과와 자료 열람만 가능한 효과 구분 | 기본 직접 DPS·콤보 범위 TTK·일부 고정 아케인; 상태/강공격/슬램 미지원 |

위키에서 확인되지 않은 필드는 미기재로 남긴다. 전체 콤보 시간만 있는 경우 개별 타격 시각을 균등 분할해 정밀 TTK라고 표시하지 않는다. 필요한 세부 필드는 위키의 관련 페이지·모듈에서 추가 확인하며, 확보된 정보의 범위에 맞게 결과를 제공한다. 위키의 개정이 바뀌면 원본과 기대값 차이를 함께 검토한다.

완성형 추천에 필요한 범위를 먼저 확보한다. 제한 모델의 DPS가 낮다는 이유로 위핑 운즈나 유틸리티 모드를 제거하라고 추천하지 않는다. 시뮬레이션 P10/P90은 개별 시행 결과의 분위수이며, 추정량의 통계적 신뢰구간과 구분한다.

- 적 ID와 레벨, 일반/강철의 길/특수 모드, 체력·실드·오버가드·방어력·상성·상태 면역·피해 감쇠.

### 3.2 출력

- 타격별 피해 분포와 기대값, 시간 구간별 DPS, 조건 활성화 전/후, 첫 적/연속 교전 비교.
- 직접 피해와 상태이상 피해의 분리, 피해 유형별 기여도, 방어층별 처리.
- TTK 중앙값/P10/P90, 제한시간 내 처치율, 생존곡선. 제한시간 미처치를 제거한 낙관적 결과를 만들지 않는다.
- 모드·리벤 교체 효과와 원인. 예: 이미 높은 기본 피해 버킷, 치명타 단계 경계, 상태 유지율 변화.
- 빌드 A/B 비교 시 같은 적·조건을 기본으로 고정한다. 조건이 다르면 차이를 강조한다.

### 3.3 근접 특화

스탠스는 단일 평균 배율이 아니라 순서가 있는 타격 이벤트로 저장한다. 이벤트마다 시작 시점, 모션 배율, 반복 타격 수, 강제 상태이상, 콤보 획득, 범위, 폴로스루를 가진다. 동일 무기라도 스탠스의 정지/전진/가드 동작을 구분한다. 공격속도 수치를 타격 횟수/초로 그대로 해석하지 않는다.

강공격은 준비 시간과 실제 타격 애니메이션을 분리한다. 콤보 소비와 효율, 강공격 한정 치명타 모드 배수, 강제 베기와 고유 공격을 다룬다. 글레이브·건블레이드·에너지 파동·익절티드·조우·인카논은 검증된 어댑터가 있어야 지원한다.

컨디션 오버로드는 해당 타격 직전의 유효한 상태 종류를 사용한다. 블러드 러시·위핑 운즈는 콤보 변화에 따라 갱신한다. 갤버나이즈드·버서커·세트 효과·킬 트리거는 초기 상태와 유지율을 구분한다.

상태이상 엔진은 확률, 100% 초과 발동 수, 피해 가중치, 강제 발동, 중첩 제한, 틱 시점, 지속 시간, 재적용을 관리한다. 베기·화염·독성·전기·가스·폭발과 바이러스·부식·자성 등의 영향을 별도 규칙으로 구현한다. 세력 배율의 반복 적용 같은 예외는 출처 규칙과 독립 계산 예제로 검증한다.

## 4. 리벤 시뮬레이터

### 4.1 옵션 상·하옵 분석

입력은 무기/파생형 ID, 리벤 랭크, 옵션 ID와 순서, 표시값과 단위, 양옵/음옵 구성, 고정/접합 여부, 표시 당시 무기, 기질 스냅샷이다. 기질의 점 개수를 실제 수치로 대신하지 않는다.

자동 판정 시에는 옵션별 기준 상수, 무기 기질, 양옵·음옵 구성 계수, 랭크 보정, 허용 롤 범위를 버전이 있는 데이터로 불러온다. 아직 확인하지 못한 계수나 접합 수치 공식을 추정해서 채우지 않는다.

출력은 이론 최솟값/최댓값, 표시값에 대응하는 가능한 내부 수치 구간, 범위 내 위치, 상한과의 차이다. 예를 들어 화면상 최댓값과 같아도 반올림 때문에 정확한 최대 롤이라고 단정하지 않는다. 수치 범위 내 위치와 옵션이 나올 확률은 서로 다른 값이다. 음옵은 크기와 유용성이 반대일 수 있고, 빌드에 따라 영향이 달라진다.

획득 불가능한 옵션 조합, 중복 옵션, 무기별 옵션 풀, 음옵 가능 여부를 검증한다. 현재 v0.5의 후보 선택기는 양옵/음옵 개수와 중복만 검사하며 실제 획득 가능성을 보장하지 않는다.

### 4.2 접합

기준 규칙은 PC Update 44.1.0이며 44.1.1에서 접합 리벤 순환 시 쿠바 비용이 잘못 두 배가 되던 버그와 약점 피해 접합 적용 오류가 수정된 것을 확인했다. 한 리벤의 호환되는 두 옵션에서 가능한 접합 후보를 모두 나열한다. 선택한 두 옵션과 유지되는 나머지를 보여준다. 접합 결과 종류와 무작위 대체 슬롯을 구분한다. 기존 접합 옵션의 제거·재순환은 명시적 상태 전이로 관리한다.

초기 구현은 근접 전용 5개와 공통 9개 조합의 호환 관계만 제공한다. 수치 합산으로 결과를 만들지 않는다. 접합 양옵과 대체 옵션 부호를 표시하고 수치·대체 옵션 종류는 미확정으로 둔다. 예: 근접 피해 + 상태이상 확률 → 상태이상 피해 접합 후보.

접합 유지로 옵션 구성의 개수가 고정되는 규칙, 일반 옵션 고정, 고정에 따른 쿠바 비용, 고정 해제, 재순환을 각각 모델링한다. 접합 보존을 일반 옵션 고정 비용과 혼동하지 않는다. 향후 결과 수치와 옵션 추첨 분포가 검증되면 기대 결과·범위·목표 도달 확률·쿠바 비용 분포를 제공한다.

### 4.3 모딩 연결

리벤은 일반 모드 슬롯 하나를 차지한다. 옵션 순서, 음옵, 속성 결합, 조건부 효과를 일반 효과 파이프라인에 주입한다. 접합 복합 속성은 기본 원소 조합과 구분한다. 단순 옵션 등급이 높아도 실제 빌드 효율이 낮을 수 있으므로 양쪽을 함께 표시한다.

## 5. 성유물 보상 화면과 마켓

보상 선택 화면의 한국어 아이템명·희귀도·개수·포르마·설계도 등을 작은 화면 영역에서 인식한다. OCR 신뢰도, 후보명, 사용자 수정 기능을 제공한다. 자동 인식 결과는 정규화된 게임 ID → 마켓 ID로 연결한다.

Warframe.market v2 어댑터를 사용한다. 판매/구매 호가, 접속 상태, 플랫폼/크로스플레이 조건, 거래량 또는 통계의 제공 여부, 조회 시각을 보존한다. 판매 호가를 실제 체결가라고 부르지 않는다. 부품과 세트 가격, 품목 랭크를 혼동하지 않는다.

일반 API 한도는 공식 문서의 초당 3회 기준으로 시작하고 전역 큐·중복 요청 병합·캐시·429 재시도 정책을 둔다. 세부 한도는 엔드포인트별로 관리한다. 초기 제안 캐시는 아이템 사전 24시간, 호가 30~60초이며 실제 이용 조건과 반응성을 검증해 조정한다. 오프라인·오래된 값·품목 미인식은 구분한다.

오버레이에는 비교에 필요한 가격·듀캇·보유 여부와 데이터 시각만 간결하게 표시한다. 보상 선택을 자동 조작하지 않는다.

## 6. 마스터리 계획

보유/제작 완료/마스터리 획득 여부, 재료·설계도·MR 제한·퀘스트·평판·클랜 연구·선행 장비를 저장한다. 제작 가능성, 부족 재료, 예상 파밍 노력, 제작 대기, 슬롯과 비용을 설명한다.

추천 점수 하나로 시간을 단정하지 않는다. 즉시 제작 가능, 재료 적게 필요, 다음 해금에 필요한 장비 등의 기준을 선택하게 한다. 재료로 소모되는 장비는 먼저 마스터리를 획득하도록 안내한다. 포르마 재랭크로 일반 장비의 마스터리를 다시 얻는다고 계산하지 않는다. 40랭크/조립식 장비의 예외는 별도 규칙으로 검증한다.

랭작 효율은 현재 해금 콘텐츠, 솔로/분대, 부스터, 플레이 성향, 무기 제약에 따라 달라진다. 실측 또는 사용자가 기록한 시간 범위를 이용하고 확정 소요시간을 약속하지 않는다.

첫 저장 형식은 스키마 버전을 가진 JSON이다. 향후 장비·시세·프로필 규모가 커지면 SQLite를 사용한다. UI와 엔진은 분리해 스냅샷 입력만 작업자에게 넘긴다. 빌드와 데이터 버전이 다르면 조용히 재해석하지 않는다.

카탈로그 v0.1은 WFCD의 커밋 `4a73b2fb016d7a79ec0694aec42a66778d762288`에서 무기 3종과 모드 17종을 선택했다. WFCD는 공식 계산 명세가 아닌 커뮤니티 데이터이다. 공격 데이터는 `Normal Attack` 필드를 사용하고 공속은 원본 `fireRate`를 보존했다. 표시 반올림과 원본 float 오차를 구분한다. 한국어 이름은 v0.3에서 공식 ko Public Export로 대체했고 영문 이름과 내부 ID를 함께 저장한다.

스탠스 v0.2는 WF Wiki `Module:Stances/data`의 revision `2815256` (2026-10-02T11:57:23Z)을 고정해 수집했다. 니카나 3종, 톤파 2종, 헤비 블레이드 3종의 총 8스탠스·32콤보를 수록한다. `data/stance-source-records.json`에는 선택한 원문 테이블을, `data/stances.json`에는 정규화 결과와 출처 메타데이터를 저장한다. Lua 코드를 실행하지 않고 제한된 테이블 구문만 해석한다.

Blind Justice의 한 원문 필드에 따옴표 없는 `Knockdown` 식별자가 있어 `unresolved:Knockdown`으로 보존했다. 파서가 의미를 임의 확정하지 않는다. 해당 표기는 원문에서 확인해야 할 변환 항목이며 사용자의 게임 실측 과제가 아니다. 물리 피해 배율·상태확률 배율·슬램 표기도 함께 보존한다.

자료는 WARFRAME Wiki contributors의 CC BY-NC-SA 3.0 고지를 동봉한다. 배포한 정규화 스탠스 자료에도 같은 라이선스를 적용한다. 다른 데이터·자체 코드·Wanted Sans는 각자의 라이선스와 구분한다.

## 8. 성능과 디자인

C#/.NET 8 WPF를 선택한 이유는 Windows 네이티브 연동, 계산과 UI 분리, 웹 엔진 상주 없이 배포할 수 있다는 점이다. C++/Rust는 측정에서 병목이 확인된 캡처나 OCR 경로에 한해 검토한다.

입력이 바뀌면 기본 수치를 즉시 계산한다. 반복 시뮬레이션은 180ms 디바운스 후 작업 스레드에서 실행하고 오래된 결과를 폐기한다. 동시에 실행하는 시뮬레이션은 하나로 제한한다. 화면이 정지했을 때 앱 자체 주기 작업과 애니메이션을 돌리지 않는다.

최종 성능 목표 초안: 유휴 앱 CPU 1% 미만, 보통 빌드 기본 계산 P95 16ms 이내, 반복 시뮬레이션 UI 비차단, 초기 모딩 화면 작업집합 150MiB 이내. 모두 실제 장비·게임 병행 측정으로 확인해야 하는 목표이며 보장값이 아니다. OCR 탑재 후 별도 예산을 정한다.

디자인은 기본 다크 테마의 서리 유리 레이어, 차가운 파랑·보라의 배경 빛, 얇은 반사 테두리, 둥근 조작부, 조밀하지 않은 수치 위계를 사용한다. Wanted Sans Regular/SemiBold/Bold를 내장한다. Windows 11 지원 환경에서는 장기 실행 창에 적합한 시스템 Mica를 사용한다. 현재 버전은 유리 소재의 방향을 잡은 첫 패스이며 Apple Liquid Glass의 실시간 굴절 셰이더를 구현한 것은 아니다.

스크롤바·팝업·입력창은 다크/라이트 리소스에 함께 반응한다. 보관함 → 슬롯 드래그는 장착, 슬롯 → 슬롯은 랭크를 보존한 교환, 슬롯 → 보관함은 해제다. 중복 계열은 차단하고 변경 즉시 기본 수치를 갱신한다. 모드 순서는 위 1→4, 아래 5→8이다.

경량 모드는 테마와 독립적이며 시스템 배경과 장식 레이어를 끄고 불투명 재질로 바꾼다. 선택 상태를 색만으로 구분하지 않으며 키보드 탐색, DPI 100/125/150/200%, 고대비·투명도 감소 설정을 최종 접근성 수용 기준에 넣는다.

| M3 | 리벤 범위 자동화·접합 수치·고정/순환·빌드 연결 | 화면 반올림 역추정과 공식/위키 규칙 대조, 불명확한 확률 표시 | M1과 데이터 준비 병행 |

| M5 | 마스터리 제작/랭작 계획 | 보유 정보 기반 설명 가능한 추천과 예외 처리 | 예정 |

M0에서 실제 적 레벨/스탠스 데이터를 임의 생성하지 않는다. 현재 체력과 방어력 입력은 가상의 실험 대상이다. 리벤 수치 자동 판정과 접합 결과 수치 예측은 M0 완료 항목이 아니다.

## 10. 첫 위키 기반 계산 연결

니카나 프라임과 Blind Justice를 첫 대표 조합으로 사용한다. 이후 Sovereign Outcast/크로넨 프라임, 헤비 블레이드 3스탠스로 확장한다. 게임 실행·사용자 실측을 기다리지 않는다.

1. 고정 위키 원문과 정규화 이벤트의 타격 수·배율·강제 효과를 전수 대조한다.
2. 콤보 단위 직접 피해 합계와 공속 보정 시간을 독립 기대값으로 검사한다. 전체 동작 시간과 개별 타격 시각을 혼동하지 않는다.
3. 상태 틱·강공격·콤보 변화·CO 순서를 출처 규칙에 따라 연결하고 상호작용을 검사한다.
4. 위키에 없는 타격 시각은 미기재 상태를 유지하고, 계산 가능한 결과와 필요한 데이터 필드를 명시한다.
5. 패치·위키 개정에 따른 변경을 고정 fixture와 비교한다. 구현 회귀와 원본 변경을 구분한다.

v0.3에서 지원 콤보 선택에 따른 DPS·TTK 변화까지 연결했다. 다음은 강제 상태이상·상태 틱과 전투 중 CO/콤보 변화, 슬램/강공격 규칙이다. 원문에 없는 타격 시점을 임의로 보간하지 않는 기준을 유지한다.

### v0.4 당시 계산과 저장 계약 (이력)

스탠스의 추가 물리 배율은 해당 물리 성분에만 적용하고 원소 성분에는 적용하지 않는다. 피해 0인 회복 동작은 타격 수에서 빼되 콤보 시간에 남긴다. 슬램/미해석 규칙이 있는 11개 콤보는 조용히 일반 타격으로 계산하지 않는다.

TTK는 개별 타격 시점을 가정하지 않고 처치 타격이 속한 콤보 시작~종료 구간을 반환한다. 120초 안에 완료되는 콤보까지만 시뮬레이션하고 실제 구간 길이를 표시한다. 미처치 표본을 분위수에서 제거하지 않는다. 이 구간은 타격 시각 불확실성의 경계이며 통계적 신뢰구간이 아니다.

기존 스키마 1 빌드는 반복 타격 가정 모드로, 스키마 2는 스탠스 모드로 복원하고 기본 수용량 조건을 적용한다. 새 빌드는 스키마 3에 스탠스 ID·동작 키·위키 개정과 무기/MR 랭크·카탈리스트·스탠스 장착·슬롯 극성을 저장한다. 기존 앱은 새 스키마를 거부하여 설정을 조용히 잃지 않게 한다.

한국어 표시는 공식 Public Export의 ko manifest로 대체했다. 영문 이름과 내부 ID는 검색/연결용으로 유지하고 공식 극성·랭크별 설명을 보존한다. 표시 메타데이터 출처는 `localization-ko.json`에 기록한다. 코스트·최대 랭크가 WFCD 스냅샷과 달라지면 가져오기를 거부해 검토하게 한다.

보관함 카드는 88 DIP에 이름·코스트·극성, 장착 카드는 144 DIP에 간결한 효과까지 표시한다. 호버/키보드 포커스로 공식 효과 설명을 확인한다. 랭크 편집은 선택 카드 아래 공통 도구를 사용한다. 정렬은 보관함에만 적용한다. 보관함 코스트는 최대 랭크 기준이며 장착 코스트는 슬롯 극성을 반영한다. 동률은 한국어 이름·내부 ID로 순서를 고정한다. 장착 슬롯 순서와 원소 결합은 정렬로 바뀌지 않는다.

수용량 규칙은 Polarity revision 2814647 등 고정 위키 원문을 기준으로 한다. 일반 극성 일치 비용은 ×0.5 올림, 불일치는 ×1.25 올림이다. 초과 빌드는 장착 불가 표시와 함께 계획용 계산을 허용한다. 현재 무기 3종의 랭크 0~30·카탈리스트·최대 랭크 스탠스와 일반 슬롯 3극성/없음을 지원한다. 내장 극성 개수를 초기 슬롯에 배치하며 실제 게임 슬롯 좌표를 확정한 데이터로 취급하지 않는다. 8칸 비우기는 일반 모드를 모두 해제하고 슬롯 극성과 스탠스를 보존한다.

## 12. v0.5 전체 자료와 현재 계산 계약

전체 모듈을 수집하고 정규화한 범위와 효과 구현 범위는 DATA_COVERAGE.md를 따른다. 총기·모듈 부품 등을 포함한 911개 항목을 자료실에 등록하고, 일반 근접 228개의 Normal Attack만 기본 모딩 계산에 연결한다. 스탠스는 134개 표와 상속 포함 1,248개 동작을 보존한다. 일반 근접 호환 동작 중 1,990개 조합이 현재 직접 모델로 계산되며 5,902개는 명시적으로 거부한다.

모드 1,550개 전체 열람, 일반 근접 보관함 122개, 그중 34개 일반 직접 피해 관련 수치를 처리한다. 지원하지 않는 모드·아케인을 장착했을 때 완성된 DPS인 것처럼 표시하지 않는다. 무기 고유 발동·인카논·쿠바/테넷/코다 추가 원소·조우 조립은 기본 수치와 별도로 아직 미반영이라고 알린다.

아케인은 근접 1개·워프레임 2개와 랭크·발동 여부·중첩·실드/오버실드·동결·마무리 처치 횟수를 저장한다. 10개 고정 효과와 4개 일반 직접 타격 비적용 효과를 구분하고, 전투 중 발동 시점·유지율·상태 전파는 추정하지 않는다. 도우티는 위키 예제, 듀플리케이트는 노란 치명타 조건과 독립 재추첨, 크레센도는 수동 초기 콤보로 검증한다.

새 저장 형식은 스키마 4이며 아케인·수용량·스탠스·슬롯을 포함한다. 이전의 알려진 데이터 버전만 명시적으로 변환하며 새 위키 수치로 재계산했다는 사실을 표시한다. 임의 버전은 자동 수용하지 않는다. 랭크 40 및 일반 추가 극성을 지원하고 내장 동작에는 가상의 스탠스 용량 보너스를 주지 않는다.

자료는 고정 개정·원문 해시·공식 Export manifest로 재현한다. AST 파서의 미해석 식별자와 중복 필드는 보존한다. v0.5.2는 아래 시각 설계 계약을 적용하며 Wanted Sans의 Ideal/Grayscale 렌더링과 PerMonitorV2 설정을 유지한다. 실제 다중 모니터와 게임 병행 성능은 별도 검사 대상이다.


## 13. v0.5.1 모딩 작업 공간

무기군·무기는 맨 위 한 줄, 스탠스·동작은 포르마·8칸 비우기 옆에 둔다. 수용량 사용/최대 및 초과 여부를 바로 표시하고 상세 조건은 팝업에서 편집한다. 장착 카드는 104 DIP, 보관함 카드는 68 DIP이며 두 줄 이름과 호버 상세를 유지한다. 보관함 내부만 스크롤하고 검색·정렬과 장착 슬롯은 고정한다. 상단 설정 높이는 116 DIP, 계산 방식 선택창은 32 DIP다.

최소 지원 창 1240×730에서도 보관함 카드 두 줄이 온전히 보여야 한다. 가시 영역을 넘는 자식의 높이를 성공 기준으로 삼지 않는다. 이번 레이아웃 검사와 예외는 UI_LAYOUT_051.md에 기록했다.


## 14. v0.5.2 상단 탐색과 데이터 중심 디자인

사용자 제공 InsightFlow 이미지의 검정·금색 대시보드를 시각 참고로 사용한다. 모딩 앱의 작업 구조를 유지하며 상단 64 DIP 안에 로고, 한국어 탭, 빌드 작업, 설정, 창 제어를 배치한다. 각 탭은 밑줄로 선택 상태를 표시한다. 창 이동 공간과 클릭 영역을 분리해 네이티브 히트 테스트로 검사한다.

큰 둥근 컨테이너를 제거하고 1 DIP 구분선과 8/16/20 DIP 간격으로 정보 위계를 만든다. 실제 입력·모드 카드·버튼은 4~6 DIP 모서리를 유지한다. 기본 배경 #0D0F11, 텍스트 #F0F0EE, 보조 텍스트 #A6AAAF, 강조 #E6BE5A. 리벤 보라색과 피해/치명타 의미 색상을 보존한다.

결과가 충분히 넓으면 주요 수치 4개를 한 줄로, 작은 창에서는 2×2로 배치한다. 도넛은 피해 비중과 수치, 선·면 그래프는 유효 방어력에 따른 직접 DPS, 막대그래프는 개별 타격의 기대 피해를 보여준다. 개별 타격 시각을 추정하지 않으며 장식용 데이터를 생성하지 않는다. 그래프는 변경 시에만 다시 그린다. 지원 범위와 계산식은 펼치기에서 계속 제공한다.

검증 기준과 이미지 목록은 UI_LAYOUT_052.md를 따른다. 기존 계산 지원 범위·저장 형식·자료 버전은 이번 UI 변경으로 확대되지 않는다.


## 15. v0.5.3 카드·툴팁·글자 배치

v0.5.3은 정렬 방향 아이콘, 모드 등급별 배경, 커서를 따라가는 툴팁과 글자 렌더링을 수정한다. 정렬 상태·벡터 아이콘·설명을 한 경로에서 갱신한다. 위키 내부 ID의 등급/분류를 기준으로 구리·은·금·백금·리벤 등의 정적인 카드 마감을 적용한다. 툴팁은 모니터 가장자리에서 반전하고 드래그·스크롤·화면 전환 시 닫힌다. 상세 기록은 `docs/UI_INTERACTION_053.md`에 있다.

Wanted Sans는 96 DPI Display, 고배율 Ideal 메트릭과 Grayscale을 사용한다. 카드의 색상은 등급과 Class/Polarity에 근거하고 정렬·호버 선택 상태와 구분한다. ToolTip은 포인터 이동 이벤트에서만 위치를 갱신하고 실제 모니터 작업 영역에서 반전/제한한다. 기본 본문 14 DIP/행간 22 DIP, 모드 효과 행간 23 DIP로 상세 정보를 읽을 수 있게 한다.
