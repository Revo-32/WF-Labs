# 일정 오버레이 조작·표시·전용 알림음 개편

## 사용 동작

`일정 → 오버레이 · 성유물 알림 → 위치·크기 조정`을 누르면 오버레이 위에 작은 편집 제목줄이 나타난다. 제목줄을 잡아 이동하고 창 가장자리·모서리로 크기를 조절한다. 제목줄의 `완료`를 누르면 위치·크기를 저장하고 게임 표시 상태로 돌아간다. 하단의 흰 Thumb 막대를 제거했다. 설정 창을 닫을 때도 편집 상태를 저장한다.

별도 모양의 조절 부품 대신 WPF WindowChrome의 native non-client hit testing을 사용한다. 실제 HWND에서 제목줄 HTCAPTION(2), 오른쪽 아래 모서리 HTBOTTOMRIGHT(17)을 검사하고 SetWindowPos로 이동·크기 조절을 확인했다. 일반 표시 중에는 NOACTIVATE·TRANSPARENT·TOOLWINDOW, 클릭 통과, 게임 전경에서만 표시하는 동작을 유지한다. 자동 검수에서 실제 마우스나 게임 키를 보내지 않았다.

## 화면 구성

- 불필요한 `WF Labs · 일정` 문구를 없애고 현재 시각만 위에 표시한다. 시각은 다른 일정과 동일한 KST다.
- 일정과 성유물 균열을 구분한다. 이름·상태/위치·남은 시간·자료 기준의 위계를 분리하고 얇은 선으로 항목을 나눈다. 노랑은 다음 S티어·알림 대상의 강조에 사용한다.
- 좁은 창은 상하, 넓은 창은 좌우로 구역을 배치한다. 일정 목록이 길어도 균열 구역을 화면 밖으로 밀어내지 않도록 두 구역의 스크롤을 독립시킨다. 일반 클릭 통과 상태에서 목록을 넘기려면 편집 상태로 들어가 스크롤한다.
- `현재 열린 성유물 균열`은 기본 켜짐이다. 알림 등록 여부와 관계없이 현재 균열을 볼 수 있으며 전체/강철의 길/일반/보이드 폭풍/알림 조건으로 필터한다. 알림에 맞는 균열은 태그와 색으로 구분한다.
- 목록 키가 같으면 기존 UI를 유지하고 바뀐 값만 갱신한다. 매초 전체 시각 트리를 다시 생성하지 않는다. 배경 색이 같을 때는 Brush도 다시 만들지 않는다.

## 표시 설정과 호환

설정 창의 `표시 스타일`에 다음 항목을 추가했다.

| 항목 | 범위 | 동작 |
|---|---|---|
| 배경 투명도 | 0~100% | 글자의 투명도는 바꾸지 않는다. 기본 18% 투명 |
| 글자 그림자 | 켜기/끄기 | 오버레이와 팝업의 텍스트만 적용 |
| 그림자 진하기 | 0~100% | 기본 75%, 화면 편집 중에도 반영 |
| 글자 크기 | 85~130% | 기본 100%, 타이머·목록 글자 크기 조정 |
| 알림 음량 | 0~100% | 전용 WAV의 PCM 진폭에 적용. 기본 65% |

표시할 일정은 접는 영역에 모으고, 조작 버튼·표시 스타일을 먼저 볼 수 있게 했다. 슬라이더는 앱의 검정/노랑 스타일을 사용한다. 설정은 기존 `schedules/preferences.json`에 추가하며 이전 파일의 위치·크기·알림을 보존한다. 새 설정이 없는 이전 파일에는 기본값을 적용한다. NaN·무한대·범위 밖 값은 보정한다.

새 기본 크기는 480 × 620 DIP이며 이전에 저장한 크기는 유지한다. 지원 범위는 너비 320~1100, 높이 260~1100 DIP다. 많은 항목을 표시하면 창 크기나 균열 필터를 조정할 수 있다.

## 전용 알림음

- 음원: `src/TennoForge.Desktop/Assets/Audio/schedule-notification.wav`.
- 생성기: `tools/generate_notification_sound.py`.
- 440/660/880 Hz의 부드러운 attack·감쇠를 가진 3음 신호, 0.74초, 48 kHz mono 16-bit PCM.
- 외부 샘플을 쓰지 않은 자체 합성. 원본 peak 약 0.330으로 clipping이 없다.
- SHA-256: `1f2e3a7391bb4c91f311255c30714881f8e5a14c17a91dae010896f4d64aaec6`.
- Windows 기본 알림음 호출을 제거했다. WAV를 assembly에 내장하고 SoundPlayer로 재생한다. 여러 알림은 한 번의 신호로 묶고 동시에 중복 재생하지 않는다. `알림 테스트`로 선택한 팝업/전용 소리를 확인할 수 있다.

자동 검수에서는 실제 소리를 내지 않았다. 내장 리소스·RIFF/PCM 유효성·0 음량의 무음·원본 데이터·음량 설정 저장을 검사했다. 사용자의 실제 스피커에서 들리는 크기는 OS/장치 음량의 영향도 받는다.
