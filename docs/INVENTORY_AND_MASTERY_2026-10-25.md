# 인벤토리·마스터리 도우미 구현 및 검수

2026-10-25 로컬 개발본. 공개 릴리스·설치 파일은 만들지 않았다. 기존 모딩·리벤·성유물 기능과 미커밋 변경을 보존했다.

## 사용 흐름

상단 **내 장비** → **게임에서 동기화** 또는 **목록 가져오기** → 마스터리 도우미에서 장비 선택 → 필요한 부품의 성유물 찾기 / 이 장비 모딩하기.

- **마스터리 도우미**: 보유 장비 랭작 → 제작 중 → 재료·설계도·크레딧이 준비된 장비 → 구매/획득이 필요한 후보 순으로 표시한다. 부족 부품 비용은 남은 마스터리 1,000점당 비교할 수 있다.
- **인벤토리**: 한국어 검색, 장비 분류, 보유·랭작 미완료·마스터리 완료 필터, 수량·과거 최고 랭크·현재 랭크·포르마·도금 정보를 확인한다.
- **성유물 계획**: 보유 성유물과 정련도를 바탕으로 목표 부품 확률, 판매 호가 기댓값, 두캇 기댓값, 보이드 잔영 비용을 비교한다. 게임 내 보상·정련·거래를 자동 실행하지 않는다.

## 데이터와 계산

`data/inventory-catalog.json`에 한국어 품목 11,331개, 마스터리 대상 809종, 제작식 1,488개, 성유물 정련도별 3,200개를 담았다. 정련도별 항목 수를 서로 다른 성유물 3,200종으로 표현하지 않는다. 리스·메소·네오·액시 796개 계열과 기존 레퀴엠 4개 계열이다. 기존 레퀴엠은 보유 정련도만 비교하며 추가 정련을 추천하지 않는다.

공식 한국어 Public Export의 `uniqueName`, 제작식의 `resultType`/`ItemType`, 성유물의 `rewardName`을 연결한다. 이름 유사도로 제작식과 보상을 붙이지 않는다. WFCD는 마스터리 대상·최대 랭크·구입 설계도 크레딧 등 보조 정보를 제공한다. 원본 URL·WFCD commit·SHA-256은 `data/inventory-sources.json`에 기록했다. 가져오기 스크립트는 `tools/import_inventory_catalog.py`다.

마스터리 규칙은 [공식 지원 문서](https://support.warframe.com/hc/en-us/articles/218718097-Mastery-Basics)와 [위키](https://wiki.warframe.com/w/Rank)를 따른다. 무기 100점/랭크, 워프레임·동반자·아크윙·K-드라이브 200점/랭크, 네크라메크 최대 40랭크·8,000점이다. 모아·하운드 헤드가 원본에서 `Pistols` 제품 분류에 있더라도 동반자 200점을 적용한다.

- `XPInfo` 이력과 현재 장비 XP를 분리한다. 포르마·판매·중복 장비로 과거 마스터리 점수를 다시 얻을 수 있다고 계산하지 않는다.
- 40랭크 장비는 현재 열린 랭크까지의 점수와 포르마 추가 후 최종 점수를 구분한다. 포르마 비용을 장비 부품 구매비에 몰래 포함하거나 무료로 간주하지 않는다.
- 조립 장비는 인식된 `ModularParts` 중 마스터리 핵심 부품으로 모으며, 도금 필요 여부를 표시한다. 원본에서 매칭되지 않는 부품은 추측하지 않는다.
- 제작에 소모할 보유 무기가 미숙련이면 먼저 랭작하도록 안내한다. 제작식은 보유 재료를 한 풀에서 차감하고 선행 제작식을 펼친다. 같은 품목의 복수 제작은 일괄 동시 제작 시간으로 취급하지 않는다.
- 설계도에 크레딧 가격이 있어도 보유 상태로 바꾸지 않는다. 구입 전에는 구매처·클랜 연구·퀘스트·평판 조건 확인이 필요하다고 표시한다.
- 마스터리 이력이 없으면 미획득 목록을 추측하지 않는다. 보유 목록이 일부인 경우 바로 제작 가능으로 판정하지 않는다.
- 판매 최저 호가는 성유물 기능의 12시간 저장소를 읽는다. 접속 상태·크로스플레이 설정을 공유하며 2분마다 다른 페이지가 갱신한 저장 파일을 다시 읽는다. 인벤토리 조회마다 HTTP 요청을 하지 않는다.
- 시세가 없는 거래 부품은 미확인이다. 포르마 설계도처럼 거래 불가로 확인된 보상의 플래티넘 가치는 0으로 구분한다. 오래된 시세는 따로 표시한다.

성유물 확률은 [공식 패치의 표](https://www.warframe.com/fr/patch-notes/pc/20-7-4)에 맞췄다. 동일 성유물·동일 정련도 분대만 비교하며 공개 분대의 다른 세 성유물을 임의로 가정하지 않는다. 한 보상의 확률이 p이면 n명 중 한 번 이상은 `1-(1-p)^n`이다. 판매가·두캇 기댓값은 보상 n개의 합이 아닌 **선택할 최댓값의 분포**를 계산한다. 목표는 부족 부품 중 하나를 얻을 확률이며 제작에 필요한 모든 부품을 모을 확률과 구분한다. 정련된 성유물을 더 정련할 때 목표 정련도의 전체 잔영 비용을 적용한다.

## 자동 수집 경로와 보관 범위

현재 직접 읽기 어댑터는 Windows `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`만 사용한다. 실행 중인 Warframe 프로세스의 완전한 인벤토리 JSON을 찾고 허용한 필드만 파싱한다. 게임 메모리 쓰기·DLL 삽입·계정 인증 API·nonce 사용·게임 입력·화면 활성화는 하지 않는다.

자동 동기화는 내 장비 화면을 처음 연 뒤 30초 간격으로 확인한다. 한 탐색은 6초·256MB 이내로 제한하고 다음 호출에서 이어서 찾는다. 이전에 찾은 JSON의 재판독을 사용하되 2분마다 탐색을 재개한다. 스캔 작업은 낮은 스레드 우선순위에서 수행하며 리벤/성유물 인식 중에는 새 탐색을 시작하지 않는다. 화면 캡처나 전체 화면 OCR을 인벤토리 타이머에 추가하지 않았다.

저장 위치는 `%LOCALAPPDATA%\WF Labs\inventory\snapshot.json`이다. 품목 ID·수량·랭크 이력·제작 중 목록 등 정규화한 허용 필드만 원자적으로 저장한다. 원본 계정 JSON·메모리 덤프·인증 정보·채팅·플레이어 이름은 저장하지 않는다. 종료·읽기 실패·부분 응답은 마지막 저장 목록을 지우지 않는다. 같은 폴더의 `inventory-inbox.json`에 들어오는 JSON과 문서화된 Overwolf GEP envelope도 가져올 수 있다. 이번 작업에서 Overwolf 브리지 앱을 설치하거나 배포한 것은 아니다.

[Overwolf 공식 Warframe GEP](https://dev.overwolf.com/ow-native/live-game-data-gep/supported-games/warframe/)와 공개 프로젝트의 데이터 구조를 조사했다. 직접 읽기 코드는 자체 작성했으며 타 프로젝트의 GPL 코드를 복사하지 않았다. Overwolf/AlecaFrame 설치 없이 동작하는 경로를 추가했기 때문에 임시 설치·삭제 작업은 필요하지 않았다.

## 검수와 남은 한계

검수 자료는 `artifacts/inventory-*` 및 `artifacts/riven-real-reroll-2026-10-25`에 보관한다. UI 검사는 별도 Win32 데스크톱에서 실행했으며 입력 데스크톱으로 전환하거나 게임에 입력하지 않았다.

최종 기록은 `artifacts/inventory-verification-summary.json`이다. 전체 계산 1,619개·인벤토리 집중 16개·실제 버튼/검색/Windows 읽기 UI 53개를 통과했다. 마지막 UI 검사에는 내 장비 탭의 작업 복원도 포함한다. 최종 실행 파일의 전체 `--smoke` 종료 코드는 0이다. 기존 리벤 UI 102개와 OCR 45사례 회귀도 통과했으며 완전 일치는 44사례, 잘못된 자동 확정은 0건이다. 남은 한 사례는 기존 640×360 압축 성유물 화면의 미확인 한 칸이다.

검수한 전체 실행 구성을 기존 `artifacts/riven-auto-side-app` 경로로 반영하고 파일·모델·카탈로그 SHA-256을 대조했다. 이전 실행 구성은 `artifacts/riven-auto-side-before-inventory-20261025-153131`에 보존했다. 사용자가 닫은 앱을 다시 시작하지 않았다. 이 로컬 반영은 공개 릴리스나 설치 파일 생성이 아니다.

- 핵심 검사는 포르마/과거 이력·부분 목록·JSON envelope·허용 필드·저장 복원·제작 비용·도금·40랭크·성유물 확률/기댓값·정련 비용·시세 누락을 포함한다.
- 실제 Win32 메모리 영역 열거와 읽기는 **격리된 검수 프로세스의 시험 JSON**으로 검사했다. 이는 실제 워프레임 계정의 인벤토리를 읽었다는 증거가 아니다.
- UI는 파일 가져오기 버튼, 손상 파일의 기존 목록 유지, 검색·분류, 제작 목표에서 성유물 이동, 모딩 화면 이동, 세 페이지와 100/125/150% 렌더링, 버튼 경계를 검사했다.
- 현재 실제 워프레임은 종료되어 있다. 실제 계정 JSON의 존재 위치·내용·신선도, 미션 복귀/아이템 제작/계정 전환 뒤 연속 갱신은 **미검증**이다. UI의 직접 읽기는 시험 지원으로 표시했다. 메모리에 유효한 오래된 응답 사본이 남을 가능성도 있어 읽은 시각을 서버 동기화 시각으로 표현하지 않는다.
- 마스터리 대상 809종은 정규화한 카탈로그 범위다. 인트린직·성계/접합점·Plexus 등 모든 마스터리 점수원을 합산한 계정 총점 계산기는 아니다. 확인되지 않은 모듈 부품 매핑은 남을 수 있다.
- 클랜 연구·퀘스트·평판 해금 전체는 계정에서 확인하지 못한다. 설계도 미보유 상태에 이를 표시한다. 획득처까지 자동으로 모두 해금되었다고 판단하지 않는다.
- 장비 제작 후보별 비용은 독립 비교다. 여러 추천을 동시에 제작할 때의 재료 배분 최적화, 거래 세트와 낱개 조합의 전역 최저가, 실제 파밍 시간의 최적화는 이번 구현에 포함하지 않았다.
