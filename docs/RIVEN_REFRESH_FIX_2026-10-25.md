# 리벤 전환·모드 목록 이탈 수정

## 재현과 원인

사용자 첨부 화면에서 시암 카드가 열렸는데 이전 인노뎀 수치가 남아 있었고, 모드 목록으로 나간 뒤에도 양쪽 창이 남아 있었다.

- 자동 감지는 이전에 읽은 옵션의 좌표를 추적했다. 새 카드의 글자·배치가 크게 바뀌면 이전 좌표에 들어온 애니메이션 때문에 안정 조건을 만족하지 못하면서 이전 결과는 계속 표시될 수 있었다.
- 보라색 글자 후보만으로 상세 카드 여부를 판단해, 여러 리벤 이름이 나열된 모드 목록도 후보로 남았다.
- 시암의 잠긴 접합 옵션은 흰색이다. 보라색 전용 전처리에서는 이 줄이 사라졌다. 팩션 피해 `×0.58` 표기도 기존 부호+퍼센트 파서와 달랐다.

## 변경

- 기존 판독 서명과 큰 차이가 생기면 안정 조건·재판독 대기 시간보다 먼저 기존 결과를 무효화한다. 이전 좌표를 버리고 새 화면 후보로 초기 판독을 시작한다.
- 무효화 시 양쪽 실제 오버레이 창, 이전 결과 캐시, 글자 추적 영역을 함께 제거한다. 상세 화면을 떠나면 후보 없음 두 샘플 후 닫는다(기본 샘플 간격 750ms).
- 넓은 화면에 반복되는 카드 이름 행을 가진 모드 목록은 상세 카드 후보에서 제외한다. 목록에서 대기할 때 OCR을 반복하지 않는다.
- 이미 읽은 영역에서는 보라색뿐 아니라 잠긴 흰색 옵션의 변경도 추적한다.
- 일반 카드의 기존 보라색 OCR 경로를 유지하고, 교차 확인에 실패하면 잠긴 흰색 글자를 포함하는 추가 경로를 사용한다. 이 경로는 글자 확대, 팩션 줄바꿈 영역 확장, 카드 테두리와 MR/순환 횟수 푸터 분리, 행별 판독을 수행한다. 숫자·옵션 이름을 추측해서 채우지 않는다.
- 잠금/원소 아이콘이 숫자나 기호로 읽히는 경우 옵션명 앞의 아이콘 영역만 정리한다. 알 수 없는 영문·한글 이름이나 수치는 자동으로 수정하지 않는다.
- 팩션에 한해서 `×`, `x`, `X` 배율 표기를 받는다. `×0.58`은 -42%로 변환하고, 소수 두 자리 배율의 반올림 범위에 맞춰 퍼센트 기준 ±0.5의 정밀도를 유지한다. 등급과 접합 계승 구간에도 이 정밀도를 연결한다. 다른 옵션을 배율로 추측하지 않는다.
- 다른 오버레이의 순서·포커스를 건드리지 않는 기존 위치 추적·캡처 정책을 유지했다.

## 검증

- 집중 Core: 57개 통과.
- 전체 Core: 1,587개 통과, 실패 0개. `artifacts/riven-refresh-2026-10-25/core-all.log`.
- 최종 OCR·UI·상호작용: 61개 통과. `artifacts/riven-refresh-2026-10-25/final-ui-2/checks.json`.
- 전체 WPF smoke: 통과. `artifacts/riven-refresh-2026-10-25/smoke/ui-check.json`. 전체 화면 검사는 수정 초기 빌드에서 수행했으며 이후 OCR 경로 보완은 위 최종 61개 검사에서 재검증했다.
- 실제 시암: 치명타 피해 110.3%, 접합 상태이상 피해 108.6%, 전기 95.2%, 인페스티드 배율 0.58(-42%)를 네 옵션으로 교차 확인했다.
- 실제 인노뎀 연속 16프레임: 최초 OCR 1회, 같은 옵션에 추가 OCR 없음. 일반 OCR 경로를 유지하여 회귀를 해소했다.
- 실제 첨부 화면을 같은 크기 프리뷰로 정규화해 인노뎀 → 시암 → 모드 목록 → 인노뎀 순서를 재생했다. 배열 크기 차이로 전환 검사가 우연히 통과하지 않도록 동일 640×360 프리뷰를 사용했다. 이는 감지 상태 머신 검증이며 게임 지원 최소 해상도 변경이 아니다.
- 목록 사진을 1920/2560/3440px로 변환해 모두 후보 제외를 확인했다. 목록에 머무르는 동안 재판독이 없는 것도 확인했다.
- 격리 Win32 데스크톱에서 두 네이티브 창을 띄운 뒤 실제 무효화 메서드가 두 창과 캐시·좌표를 모두 제거하는지 검사했다. 사용자 데스크톱을 전환하거나 게임에 키를 입력하지 않았다.
- 최종 시암 좌우 렌더링을 직접 열어 잘림·등급·음옵 표시를 확인했다.
