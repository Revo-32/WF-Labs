# 리벤 오버레이 재생성 깜빡임 수정

사용자 확인: 이전 리벤 수치가 남는 현상은 최신 화면 캡처 수정 후 해결됐지만, 커서 이동이나 화면 변화 때 좌우 창이 꺼졌다 켜졌다 했다.

## 원인과 변경

- 변경 감지와 OCR 시작 경로가 기존 오버레이를 닫고 결과마다 새 네이티브 창을 만들었다. 카드 애니메이션·커서에 따른 미세 이동도 재판독을 유발하므로 창 재생성이 반복됐다.
- 자동 재판독 시 두 창을 유지한다. 재확인 중에는 고정 높이 상태 줄에 `변경 확인 중 · 이전 결과`를 표시하여 이전 값이 새 카드의 확정 결과처럼 보이지 않게 한다.
- 옵션·구성·확인 상태가 같으면 내용도 다시 만들지 않는다. 다른 옵션으로 확정되면 동일 HWND의 내용만 바꾼다. OCR 소요 시간이나 텍스트 좌표 차이는 내용 변경 조건에서 제외한다.
- 640px 프리뷰의 글자 마스크를 ±3px 정렬하여 비교한다. 단순 이동은 무시하지만 글자 자체의 변화는 계속 탐지한다. 실제 게임 화면의 원본 캡처 방식은 이전 수정 그대로 유지한다.
- 상세 카드 이탈·게임 전경 이탈에서는 창을 닫는다. 같은 화면의 재판독과 실제 이탈을 구분한다.

## 검증

- 집중 Core 검사 58개 통과. ±3px 평행 이동을 무시하면서 글자 일부의 실제 변경은 재인식하는 검사 포함.
- 리벤 OCR·전환·UI 검사 66개 통과. 실제 인노뎀·시암·모드 목록 스크린샷과 기존 애니메이션 프레임을 재생했다.
- 동일 결과 20회 반복 시 콘텐츠 재생성 없음, 다른 결과 적용 시 좌우 HWND 유지, 목록 이탈 시 양쪽 창과 이전 결과 무효화를 확인했다.
- 전체 Core 1,588개 통과, WPF smoke 통과. 해당 결과는 `artifacts/riven-steady-2026-10-25/core.json` 및 `smoke/ui-check.json`에 기록했다.
- 새 상태 줄을 포함한 실제 WPF 콘텐츠 렌더링을 확인했다. 격리 데스크톱 검사는 사용자 데스크톱을 전환하거나 게임 입력을 보내지 않았다.
- 실제 실행의 HWND·표시 문자열을 `tools/observe-riven-client.ps1`로 제한된 횟수만 관찰한다. 결과는 `artifacts/riven-steady-2026-10-25/live-standalone/client.jsonl`에 있다.
- 첫 배치에서는 framework-dependent 출력과 기존 self-contained 런타임 파일이 섞여 정상 시작되지 않았다. 해당 폴더를 별도로 보존한 뒤 새 self-contained 출력 전체를 배치했다. 정상 CLR 로드와 현재 시각의 인식 상태, 양쪽 실제 창 표시를 확인한 뒤 실행 완료를 안내했다.
- 실제 앱의 인노뎀 관찰 14샘플에서 재판독 중에도 좌우 HWND `1117146`/`2425636`이 유지됐다. 이후 감지 이탈 구간에서는 창이 없어졌고, 시암은 새 옵션으로 표시됐다. 사용자의 커서 이동 전체를 녹화한 결과라고 주장하지 않는다.

후속 사용자 화면에서 단위 없는 사거리 누락이 발견되어 실행본은 아래 별도 기록의 수정본으로 교체했다. 이전 깜빡임 수정은 유지했다.

## 히루도 사거리 후속 수정

- 사용자 이미지: `artifacts/riven-range-2026-10-25/hirudo.png`.
- 수정 전 OCR 원문은 `+2 사거리`를 정확히 포함했지만 파서가 `단위 확인: +2 사거리` 오류를 냈다(`before/cropped-recognition.json`). OCR 글자 인식 실패가 아니라 한국어 게임 표기 수용 누락이었다.

## 범위와 한계

±3px 정렬은 모든 원근 변화나 커서 가림을 없애는 처리가 아니다. 필요한 재판독은 계속 수행하되 창 재생성을 하지 않는 것이 이번 수정의 핵심이다. 저장된 화면 재생과 실제 사용자의 커서 조작 확인은 구분해서 보고한다.
