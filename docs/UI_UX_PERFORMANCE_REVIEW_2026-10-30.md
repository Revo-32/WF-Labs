# 강화 UI·UX·성능 검수 · 2026-10-30

사용자가 강철의 길 범람 연속 테스트를 진행하는 동안, 기존 실행 파일을 교체하지 않고 별도 Win32 데스크톱에서 검수했다. 해당 데스크톱으로 전환하지 않았고 게임 키·마우스 입력, 실제 화면 캡처, 전역 단축키 등록을 사용하지 않았다. 이번 검수는 구현 담당자의 과제 중심 검토와 UI Automation·렌더링 검사이며, 별도의 독립 검토자가 참여한 것으로 표시하지 않는다.

## 사용자 과제로 확인한 기준

- 처음 들어왔을 때 현재 상태와 다음 행동을 알 수 있는가.
- 입력·후보 이동·확정·취소가 구분되고, 검색만으로 선택을 바꾸지 않는가.
- 결과가 없는 이유와 정상 상태로 돌아가는 행동을 함께 제공하는가.
- 작은 창에서 상세 정보를 펼쳐도 기본 작업 목록에 접근할 수 있는가.
- 일부 동기화·이전 오류·현재 판독 상태를 혼동하지 않는가.
- 정보량과 판독 정확도를 유지하면서 불필요한 생성·반복 연산을 줄일 수 있는가.

탐색과 선택은 [Microsoft의 탐색 설계 기준](https://learn.microsoft.com/en-us/windows/apps/design/basics/navigation-basics), 키보드·팝업·초점은 [Windows 키보드 상호작용 기준](https://learn.microsoft.com/en-us/windows/apps/design/input/keyboard-interactions)을 참고했다. 기존의 상단 탭·밑줄·검정/노랑 팔레트·인게임 의미 색을 유지한다.

재료 검색은 설계도 1,163종이 있는 검수 목록에서 20회 입력·레이아웃 갱신을 약 **65ms**, 할당 약 **4.6MB**로 처리했다. 이 수치는 새 구현의 해당 검사 프로세스 측정값이며, 이전 구현 대비 감소율을 측정한 수치는 아니다. 검색 중 설계도 ItemsSource와 스크롤 구역이 재생성되지 않는 것도 검사했다.

## OCR 후처리 최적화

한국어 CTC의 한 행은 11,947개 문자 점수를 비교한다. 개선한 `OcrArgMax`는 현재 최댓값을 넘을 수 없는 SIMD 블록을 건너뛰고, 개선 가능성이 있는 블록만 기존의 엄격한 `>` 비교로 확인한다. 첫 동률·NaN·무한대·부호 있는 0의 선택 규칙을 보존한다. 모델 가중치·신뢰도·문자 집합·자동 확정 기준은 변경하지 않았다.

554개 수치 사례에서 기존 선택과 일치했다. 96행×11,947개×12회 비교를 같은 프로세스에서 번갈아 측정해 기존 **11.6~12.8ms**, SIMD **3.2~3.4ms**였다. JIT 최적화가 되기 전에는 오히려 느린 후보였으므로 최적화된 경로끼리 비교했다. [ONNX Runtime C#의 메모리 접근 문서](https://onnxruntime.ai/docs/tutorials/csharp/basic_csharp.html)도 검토했으며, 이미 출력 Span을 재사용하던 부분을 새 성과로 집계하지 않았다.

전체 공개 리벤 45장에서는 기존 연산과 새 연산 모두 **45/45 정확, 잘못 자동 확정 0개**였고, 카드 결과 전체도 동일했다. 같은 새 실행 파일에서 연산만 전환한 측정은 다음과 같다.

| 공개 카드 45장 | 기존 scalar | SIMD |
| --- | ---: | ---: |
| 중앙값 | 0.596초 | 0.591초 |
| P95 | 0.929초 | 1.003초 |
| 최댓값 | 2.145초 | 1.773초 |

순수 후처리의 개선을 전체 OCR의 3.7배 개선으로 표시하지 않는다. 게임 병행 중 서로 다른 프로세스에서 순서대로 측정한 값이라 시스템 부하를 통제한 정밀 A/B 실험도 아니다. 전체 처리 시간에서 의미 있는 개선은 입증되지 않았고, 결과 동등성과 해당 연산의 비용 감소를 확인한 단계다.

독립 블록 판독을 먼저 실행해 후속 판독을 줄이는 후보도 시험했다. 45/45였지만 중앙값 0.604초로 전체 개선을 확인하지 못해 채택하지 않았다. 이 실험 소스·결과는 작업 폴더에만 보존하며 최종 앱에는 포함하지 않는다.

사용자가 실행 중인 OCR 시험 빌드를 OS 프로세스 속성으로만 180초 동안 351회 읽었다. 입력·포커스·화면·모델·설정은 변경하지 않았다. CPU는 논리 프로세서 16개 전체를 100%로 환산한다.
