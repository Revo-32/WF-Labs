# 한국어 공용 OCR 추가 학습

## 모델과 데이터

`src/TennoForge.Desktop/Assets/Ocr/wfkor.traineddata`는 기존 tessdata_best/kor의 LSTM 가중치를 추가 학습한 모델이다. 사전·정규식 변경만을 학습이라고 부르지 않는다. 같은 폴더의 `wfkor.model.json`에 기반 모델, 학습 범위, 평가 수치, SHA-256을 기록한다.

기존 한국어 문자 집합은 1,158개였다. 일부 장비명 글자와 ASCII x가 없어 첫 시험에서 학습 데이터가 건너뛰어졌다. 공식 언어 자료를 이용해 한글 완성형 11,172자와 필요한 ASCII·기호를 포함하는 총 11,307개 문자 집합을 구성하고 이전 네트워크 코드를 매핑했다. 이는 구성 범위이며 모든 글자의 충분한 학습·검증을 뜻하지 않는다. 확장 학습에서는 문자 미지원에 따른 건너뛰기가 0이었다.

- 학습 810줄: 실제 인노뎀·히루도·성유물 화면의 글자 줄과 합성 한국어 이름·옵션·숫자 문장.
- 선택용 검증 80줄: 시암 원본은 학습에서 제외했다.
- 평가 82줄: 팽과 별도 성유물 화면 원본은 학습에서 제외했다.
- 같은 원본의 크기 변형은 같은 분할에 묶었다. 분할 사이 원본 그룹 및 동일 이미지 해시 중복을 검사했다.
- 합성 글꼴은 Noto Sans CJK KR, 맑은 고딕, Pretendard다. 클라이언트의 압축 폰트 자산 이름은 관찰했지만 게임 폰트를 추출하지 않았다.
- CPU에서 확장 모델 4,000회 학습 후 실제 화면 비중을 높여 계속 학습했다. 최종 반복의 모델보다 검증 화면의 숫자·부호가 좋은 중간 내보내기를 선택했다. 기반 모델과 기존 영어 모델은 보존한다.

## 평가

같은 Tesseract CLI, 같은 이미지, PSM 7로 비교했다. 공백과 ×/x 및 −/- 차이만 정규화했고 다른 잡문자는 오류로 센다.

| 지표 | 기존 kor | 추가 학습 wfkor |
|---|---:|---:|
| 평가 전체 문자 오류율 | 1.94% | 0.49% |
| 평가 전체 줄 일치 | 69/82 | 78/82 |
| 실제 화면 문자 오류율 | 8.45% | 1.41% |
| 실제 화면 줄 일치 | 4/7 | 6/7 |

실제 평가 화면은 두 원본에서 잘라낸 7줄로, 넓은 일반화의 증거로 과장하지 않는다. 남은 한 줄은 번개 아이콘이 #으로 읽힌 경우다. 팽 세 옵션의 수치·부호·%는 올바르게 읽었다. 순수 문자 평가와 품목 이름·리벤 의미 검증을 거친 제품 결과를 구분한다.

## 제품 연결

- `OcrModels`에서 모델을 공통 관리한다. FHD 이상 성유물과 리벤이 wfkor를 사용한다. 저해상도 과거 성유물 이미지 가져오기는 기존 kor를 사용하며 결과에 실제 모델을 기록한다. 실시간 캡처 최소치는 FHD다.
- 긴 옵션 명칭은 사전의 유일한 후보와 한 글자만 다를 때 정규화한다. 짧은 원소 이름이나 숫자·부호·누락 단위를 추측해 채우지 않는다. 게임에서 생략하는 사거리·두께 꿰뚫기의 단위는 해당 속성과 명확히 연결한다.
- 한글과 숫자를 별도로 읽고 다른 전처리에서도 수치·부호·단위가 일치해야 한다. 완전하고 유효한 한 판독이 옵션 구성·순서를 제공해야 한다. 동일 판독 객체를 중복 근거로 세지 않으며, 반복되는 다른 숫자가 있으면 자동 확정을 거부한다.
- 글자 줄 경계와 전체 판독 폭을 구분한다. 테두리 장식을 제거하면서 화염 아이콘 뒤의 짧은 이름이나 첫 부호·숫자를 자르지 않게 한다.
- 감지 영역 끝의 긴 팩션 줄에 여백을 준다. 넓고 모호한 영역은 원본을 먼저 읽고, 잘라낸 영역이 검증되지 않으면 원본으로 재시도한다. 실제 좌표계를 보존해 다음 변경 감지에 매핑한다.
- 교차 확인이 충족되면 추가 판독을 생략한다. 기존 좌우 오버레이 창 재사용, 재확인 중 이전 결과 표시, 카드 이탈 시 닫기를 유지한다.

## 재현과 검수

실험 폴더는 `E:/CODEX/Workspaces/WFLabsOcrTraining`이며 원본·줄 좌표·정답·해시는 `dataset/manifest.json`에 있다. 원본 게임 이미지와 합성 글꼴 파일은 모델 배포에 추가하지 않는다. 도구는 전용 폴더에 추출했고 시스템 PATH나 .NET SDK를 변경하지 않았다.

Tesseract 5.5.3으로 학습했다. 해당 배포 묶음의 ICU/C++ DLL에서 문자 집합 도구 의존성 오류가 확인돼 그 도구에는 정상 동작한 5.5.0 묶음을 사용했다. 제품은 기존 .NET wrapper 5.2.0을 유지한다.

```powershell
.venv/Scripts/python.exe -X utf8 tools/ocr_training.py prepare
.venv/Scripts/python.exe -X utf8 tools/ocr_training.py convert
.venv/Scripts/python.exe -X utf8 tools/ocr_training.py charset
.venv/Scripts/python.exe -X utf8 tools/ocr_training.py train --run run-new --iterations 4000 --real-weight 5
.venv/Scripts/python.exe -X utf8 tools/ocr_training.py eval --model <모델 파일> --split validation --output <결과 JSON>
```

제품 경로는 `--ocr-benchmark-check tests/fixtures/ocr-benchmark.json <결과 폴더>`로 비교한다. 기준 모델을 강제할 때만 검수 프로세스에 `WF_LABS_OCR_MODEL=kor`를 지정한다. 저장된 이미지로 검사하며 창 활성화나 게임 입력을 하지 않는다.

- Core 1,595개 통과, 실패 0개. WPF 전체 smoke도 격리 데스크톱에서 통과했다.
- 리벤 인식·전환·UI 78개 통과. 실제 인노뎀·히루도·팽·시암, 전체/자동 경로, 배율, 좌우 창 재사용·종료, 상충 판독의 자동 확정 거부를 포함한다.
- 조기 종료 최적화가 포함된 마지막 실행본에서도 리벤 78개가 통과했다. 화면 벤치마크는 18개 모두 원래 회귀 기준을 충족했고, 17개는 전체 결과가 정확히 일치했다. 잘못된 품목 자동 확정은 0건이었다. 결과는 `artifacts/ocr-trained-final-validation/`에 기록했다.
- 인노뎀·히루도·팽·시암의 전체/자동 두 경로가 모두 일치했다. 자동 경로 시간은 각각 3.00/2.54/4.95/7.43초였다. FHD 이상 성유물 두 화면은 각 4개 보상을 전부 자동 확정했고 1.80/1.38초였다. 이는 저장 화면의 OCR 경로 시간이며 실제 이벤트 감지 지연이나 시세 네트워크 조회를 포함하는 실전 종단 시간이라고 부르지 않는다.
- 과거 640×360 어두운 화면은 기존처럼 3개 자동 확정·1개 미확정이다. 원래 회귀 기준도 3개이며 4개 모두 인식했다고 보고하지 않는다. FHD 실시간 지원 범위와 구분한다.
